## 1. 总体目标与发布口径

原六版规划沿一条主线推进（v015已失败关闭，v016待承接）：**产品闭环 → 提高直链成功率 → 真正保存 HLS 点播 → 可持续日常使用与公开预览发行 → 统一 UI 与核心交互 → 跨站视频发现与保存增强。**

| 版本 | 定位 | 用户应得到的效果 | 发布范围 |
| --- | --- | --- | --- |
| v0.1.0 | 本地产品基础版 | 发现公开直链，保存后能找回、打开、分享和管理 | 已交付的内部预览 Debug APK |
| v0.1.1 | 嗅探与直链增强版 | 更少重复/碎片干扰，支持限定的页面来源与登录条件 | 正式签名的小范围测试 APK |
| v0.1.2 | HLS 点播下载版 | 将支持的 m3u8 点播保存为独立可播放、可分享的 MP4 | 协议能力公开测试 APK |
| v0.1.3 | 日常可用公开预览版 | 支持范围明确，长任务、恢复、真机与升级有验证 | 可对外分发的公开预览 APK，不等于 v1.0 成熟版 |
| v0.1.4 | 统一 UI 与核心交互改版 | 顶部网址／底部操作、纵向标签总览、轻量工具与完整管理页，整条保存链路风格一致 | 正式签名公开预览 APK；精确身份见Release附件 |
| v0.1.5 | 跨站视频发现与保存能力增强 | 目标未完整达成，局部实现／证据保留 | **计划失败关闭，终止本版发行** |
| v0.1.6 | 通用嗅探分层增强＋承接v015欠账 | 检出即可验证、可选档保存；两挑战站端到端成品（373MB/229MB MP4）；YouTube 诊断性 No-go（用户接受，B 路线转 v0.1.7） | **已发行（code15，同 code13 长期证书）；[执行计划](history/EXECUTION-PLAN-V0.1.6.md)、[验收台账](history/RELEASE-ACCEPTANCE-V0.1.6.md)、[发行说明](releases/v0.1.6.md)** |

“发布”不是改一个版本字符串，也不自动等于上架应用商店。v0.1.3 首选本地构建的正式签名 APK 分发；商店发行需要另行确认渠道及当时要求。纯本地不排斥下载发行 APK，但应用自身不增加云端业务。

### 所有版本共同遵守

- 无自有云端存储、解析、同步、账号服务器或遥测；视频处理和数据管理在本地完成。
- **（2026-10-04 用户修订，v0.1.7 起生效）** 项目仅做本地程序、不做服务端；实现允许参考竞品应用（含闭源竞品的逆向分析）；正式文档中对非开源竞品一律不写明具体应用名称/包名。此前"正式文档不写明获取方式"的限制就此放宽为"可写参考来源、不指名"。既有"不截获按站凭据、不做云解析/远程规则下发"边界未变，如需再放宽须另行决策。

### 第二次红线修订（2026-10-04 决策，2026-10-05 随 v0.1.8 T81 留痕）

用户逐项授权放开并经 v0.1.8 计划 §0 落位（放开≠必须改）：
- **R1 许可**：Apache-2.0 锁定与 GPL 传染否决不再作为否决依据（v0.1.8 不采用，保留选择权）。
- **R2 运行环境**：Python/Node/FFmpeg 等解释器禁令解除（v0.1.8 仍不引入任何解释型运行时）。
- **R3 FFmpeg**：用户计划后续版本引入（v0.1.8 不含，时点形态另版评估）。
- **R4 规则层无网络**：解除并成为 v0.1.8 主线（受控抓取），补偿约束四条（目标域白名单/https-only、凭据不经规则头部、三重预算并入全局账本、资源中心可见性）。
- **R5 凭据**：重新定义——不做"截获"，允许规则**复用浏览器既有会话**（同注册域、UI 默认关闭逐站开启、复用 WebsiteAccessContext、不导出不落盘）。
继续有效：纯本地/无云、无远程规则下发、无 DRM/访问控制绕过、凭据不跨注册域、非开源竞品不指名、v0.1.6 §8 全部条款。详见 [v0.1.8 计划 §0](history/EXECUTION-PLAN-V0.1.8.md)。
- 只获取用户有权访问、保存的内容；不绕过 DRM、付费墙或其他访问控制。
- 候选不等于下载方案，下载完成不等于成品可用；不支持的内容说明原因，不制造假成功。
- 保留现有浏览器与文件管理闭环，不为增强嗅探而推倒重建全部架构。
- 每版先完成约定代码与页面，再测试验收；安全底线和可恢复状态随功能一同实现，不留到 v0.1.3 补救。
- 每版有冻结的支持清单、测试样本和失败分类；不承诺“所有网站都能下载”。

## 2. v0.1.0：本地产品基础版（当前已达到）

### 必须具备

1. 首页、地址与搜索、多标签、前进后退、书签、历史、快捷站点、主题和本地设置。
2. 当前标签资源嗅探、资源中心、来源证据与详情；普通卡片不铺开签名 URL。
3. 公开 MP4/WebM 等直链的确认、命名、网络选项、实际保存、任务进度和错误。
4. 取消、重新下载、来源恢复、持久化任务和重启对账。
5. 本地视频库、搜索排序、元信息/缩略图、显示标题修改、文件打开和真实文件分享。
6. 忘记记录与删除文件分开；文件丢失或不可读时不冒充可播放。

### 当前效果与证据

公开直链的“网页 → 候选 → 确认 → 保存 → 视频库 → 播放/分享 → 文件管理”已经形成闭环。

已有 33 项单元测试、API37 的 79 项功能仪器验收、API28 权限/旧 APK 覆盖迁移/小屏与外部播放器烟测；Lint 0 错误、22 提醒。上述测试主要使用自制短视频，不是广泛真实网站或真机长任务证明。

### 发布判断

可以作为 **v0.1.0 内部产品预览**。不能据此宣称已具备成熟嗅探优势、登录态下载、HLS/DASH 保存或大文件后台可靠性。当前仍是临时包名与 Debug 签名，不能把现有 APK 包装成已完成正式发行准备的安装包。

## 3. v0.1.1：嗅探与直链增强版（已验收）

实际执行决策与结果以 EXECUTION-PLAN-V0.1.1.md / V0.1.1-COMPLETION.md 为准：所有新任务统一受控，不跨包迁移，独立正式签名、公共目录与实际分享。下文保留原规划门槛。

### 核心目标

先把“已经发现的视频为何保存失败”处理好，让用户在明确支持的直链场景中更容易成功，而不是急着增加一堆普通浏览器功能。

### 必须完成

**A. 嗅探质量**

- 加强现有 DOM video/source、播放触发、延迟加载与可观测请求证据的关联；覆盖受控的同源 iframe，不宣称完整跨域 iframe/Service Worker/MSE 支持。
- 合并同一地址的多种证据，改善标题与来源；不随意删除 query 来去重，不把不同签名、不同清晰度武断合并。
- 同一资源多种表现只在证据足够时聚合；主视频优先，降低常见片段、初始化文件与明显广告线索的干扰，不承诺自动识别所有广告。
- 页面导航、刷新、多标签与异步回调不串候选；嗅探开销有上限，不对整站无界主动扫描。

**B. 必要访问上下文：严格限定的直链子集**

- 可按需要使用当前页面 User-Agent、来源信息，以及目标地址适用的已有网站 Cookie；网站登录不是应用账号体系。
- 首版登录态范围限定为：用户在浏览器内合法登录、媒体与页面同源、使用普通 Cookie 的 HTTPS 直链。
- 支持受控的来源校验场景；不向任意目标发送完整敏感来源 URL。
- 使用可控制重定向与请求条件的本地传输路径；不把敏感凭据直接交给会自动跟随重定向的通用下载请求。
- 逐跳校验目标；跨源敏感跳转先拒绝或要求重新从页面发现，不复制上一个目标的 Cookie/Authorization。
- 不把 Cookie、Authorization 写入任务 JSON、普通日志或用户诊断导出。恢复时重新确认当前适用会话，失效则提示返回网站登录。
- 不承诺 JS 私有 Bearer Token、复杂第三方/分区 Cookie、跨站登录下载或反爬绕过。

**C. 失败处理和第一条正式发行链**

- 区分“未发现”“需要网站登录/当前权限不足”“链接过期”“网络失败”“服务器拒绝”“文件不是支持的视频”等结果；无法确定时不编造原因。
- 提供“返回来源重新发现”和合理的重试路径，不一直重试同一失效签名。
- 新传输路径具备取消、网络约束、任务持久化、基本通知与后台运行处理；系统限制或进程终止后不得显示永久假运行。
- 第一份对外 APK 前确认应用名称、正式 applicationId、图标、Release 签名及密钥的本地保管方式。
- 单独说明现有 Debug 数据向正式发行线的过渡策略并演练；不能以卸载真实应用清数据来冒充无损升级。

### 用户应该感受到

“开始播放后更容易找到目标；不是满屏碎片；部分原来在网页能播却保存失败的直链，现在可以直接保存；保存不了也知道下一步怎么办。”

### 发布门槛（全部满足）

- 新建冻结用例集，至少 12 个直链/嗅探场景，覆盖公开、签名、同源登录、来源校验、延迟加载、同源 iframe、多个标签与异常响应；支持场景全通过，不支持/失效场景行为正确。
- 至少 3 个独立真实 HTTPS 站点或部署环境、累计 10 个自有或获授权视频；记录日期、网站/WebView/系统版本及成功/失败原因，不能全用两秒 localhost 样本代替。
- 专门验证跨源重定向不泄漏凭据，注销后不沿用失效授权，日志和任务文件不含敏感请求头。
- 新传输路径至少完成 15 分钟锁屏/后台下载及中断后再启动检查；不因此宣称适配所有 OEM。
- v0.1.0 闭环无阻断回归；新签名包能安装，发行身份/旧 Debug 过渡规则清楚。

**不进入本版：** HLS 成品、DASH、直播、真正无痕、大型浏览器改版、全面跨站鉴权。

## 4. v0.1.2：HLS 点播下载版（候选实现，未正式发布）

实施实绩以 EXECUTION-PLAN-V0.1.2.md / V0.1.2-CANDIDATE.md 为准，以下门槛保留，不因已有代码而自动通过。

### 核心目标

将 v0.1.0 的“能识别 m3u8，但不能保存”升级成 **支持子集内的完整视频保存**。只保存清单、若干 TS 文件或应用内部离线缓存，均不算达到本版目标。

### 明确的首版支持子集

- 已结束的固定 HLS 点播清单；要求明确结束标记，不录制直播或持续更新的 EVENT。
- 主清单及媒体清单、绝对/相对地址、正确保留地址中的签名条件。
- 主清单内受支持档位的选择；清晰度/码率只能使用清单可靠提供的信息。
- **未加密 MPEG-TS 分片，H.264 视频 + AAC 音频，音视频在同一组分片内。**
- 在许可的访问上下文内下载；跨源公开 CDN 可无凭据访问，需跨站敏感凭据的组合不自动放行。
- 分片稳定、无时间轴不连续；首版不支持 fMP4/CMAF、BYTERANGE、独立音轨、多语言、字幕或 DISCONTINUITY。
- 所有加密组合首版均后置，包括普通 AES-128；不将“非 DRM 加密”与“DRM”混为一谈。

### 必须完成

1. 资源中心将 HLS 呈现为视频候选，解析后提供支持的档位与保存方案；不将每个分片当成一个视频。
2. 有界解析、重定向、清单/分片数量与体积限制；不盲目继承主清单 query 到子地址，也不无限递归。
3. 分片有界并发、顺序/完整性管理、有限重试、网络约束、取消、基本后台通知；缺片或访问条件变化不假成功。
4. **本地重封装为单个 MP4，不只是拼接 TS 后改扩展名。** 成功条件包含可读取轨道、预期时长与采样播放检查；不对任意文件声称完整解码校验。
5. 任务区分获取/封装/校验阶段；未知总字节就展示可靠阶段或已完成分片数，不伪造百分比。
6. 临时分片、封装输出和最终成品生命周期分开；失败/取消可清理本任务临时文件，成功后只将成品入库一次。
7. 最终 MP4 能用外部播放器打开、临时授权分享和明确删除，与已有视频库/来源功能连通。

### 用户应该感受到

“看到支持的 m3u8 后，选择档位，一次操作得到手机上的独立视频文件，不必研究分片，也不依赖本浏览器才能播放。”

### 发布门槛（全部满足）

- 最先打通一个完整技术纵切：清单 → 分片 → MP4 → 外部播放/分享；再扩大 UI 和样本，不先把大量页面做完才发现封装路线不可行。
- 至少 12 个冻结 HLS 正向/异常用例，覆盖主清单、多档位、相对地址、签名、乱序返回、缺片、过期、断网、取消和明确排除的格式。
- 至少 3 个独立真实 HTTPS 站点或部署环境的获授权 HLS 样本；不能据此宣称支持三类站点的所有视频。
- 至少 1 个 30 分钟以上有音频的点播样本：检查开头/中间/结尾、拖动、时长及声画同步；文件可跨应用分享和播放。
- 锁屏/后台基本下载通过；中断后状态可恢复对账，至少可安全重新下载。跨进程分片断点续传留给 v0.1.3，不提前宣称已有。
- 不支持的直播/加密/fMP4/独立音轨等清单有明确说明；封装失败不入库，缺片不成功。
- 全部 v0.1.0/v0.1.1 承诺继续通过，覆盖安装不丢已有成品和本地管理数据。

**不进入本版：** DASH、直播录制、加密 HLS、任意编码转码、全协议自动合并、高级播放器。

## 5. v0.1.3：日常可用公开预览版

2026-10-03：开发中候选0.1.3-rc.1 / code8。实现见EXECUTION-PLAN-V0.1.3.md；尚未通过以下全部真实发行门槛，不能视为正式发行。

### 核心目标

不再为了增加格式而扩散范围。把“支持的直链和 HLS”做成有长任务、恢复与升级证据的预览工具；真机兼容作为可选增强，并整理公开分发所需材料。

### 必须完成

**A. 下载可靠性与控制**

- 统一展示任务状态、并发队列和等待原因；Wi-Fi 约束、断网、空间不足、系统限制、授权失效分别处理。
- 对应用自管任务提供真正的暂停/继续；HLS 可验证地保留已完成分片，直链只在服务器正确支持范围请求且资源一致时续传，否则明确重新下载。
- 原系统 DownloadManager 任务继续保留诚实的系统能力，不伪造手动暂停按钮。若迁移引擎，另验证旧任务，不影响已下载文件。
- 普通进程回收与重新打开可对账恢复；设备重启、用户强制停止后的行为有清楚规则。**不承诺用户强停后仍持续运行或无人干预自动恢复。**
- 正确处理现代 Android 后台/前台服务限制、通知授权拒绝、超时，以及 OEM 省电造成的中断；提供等待或用户主动恢复，而非要求不受限常驻。
- 临时文件与容量边界明确，取消/失败/重启不产生不可管理的碎片垃圾，不对别的应用文件全局清扫。

**B. 产品与本地隐私收尾**

- 真实使用路径上的布局、键盘、返回、长标题、空态和错误文案统一；修复小屏、大字体、深色与基本横屏阻断问题，不展开全平板多栏重构。
- 提供按项清除本地历史/网站数据/临时下载的操作，明确各项影响，不能一键隐式删除用户成品。
- 基础无障碍：关键按钮语义、可触达目标、非纯颜色状态提示。
- 提供用户主动导出的脱敏诊断和本地兼容性记录，不自动上传、不导出 Cookie/鉴权头/完整敏感签名 URL。

## 8. 技术核对依据（2026-10-02）

这些材料说明技术约束，不代表本项目已实现其全部功能。

- Android CookieManager：按 URL 查询 Cookie，分区 Cookie 另有顶层分区条件；不能将网站登录简单等同于复制一份全局 Cookie。
  https://developer.android.com/reference/android/webkit/CookieManager
- Android Media3 下载指南：常规离线下载围绕 Cache 与播放器读缓存；本项目需要的独立 MP4 成品必须另有经过验证的封装/导出路径。不能把离线缓存当成已实现可分享文件。
  https://developer.android.com/media/media3/exoplayer/downloading-media
- HLS RFC 8216：主/媒体清单、结束标记、分片格式、独立音轨、加密、时间轴不连续等是不同能力；本版只选择明确子集。
  https://www.rfc-editor.org/rfc/rfc8216
- Android 前台服务超时：适用目标版本下 dataSync 等类型有运行时长及启动限制；通知/服务不保证无限后台常驻。
  https://developer.android.com/develop/background-work/services/fgs/timeout
- Android 版本与签名：versionCode 应随发行增长；正式发行身份和升级签名需要提前管理，Debug 签名不能当成正式发行准备。
  https://developer.android.com/studio/publish/versioning
  https://developer.android.com/studio/publish/app-signing

本路线图不预选新的大型框架、播放器或原生编解码 SDK。实现阶段优先复用已有 Android/GitHub 调研；确需依赖时先核对原始源码、许可证、包体积、维护状态和成品输出能力，再做最小引入。
