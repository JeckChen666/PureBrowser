# 第二轮执行计划：资源、下载与本地视频库产品化

日期：2026-10-01（Asia/Shanghai）。  
状态：**规划已落盘，T8–T14 尚未实施。**  
依据：第一轮 T1–T7 完成记录、现有代码及已确认的纯本地/产品优先方向。

## 1. 本轮目标

完成一条可以日常重复使用的路径：

**打开网页 → 发现资源 → 明确选择并保存 → 查看任务 → 关闭来源标签/退出应用 → 重新打开 → 在本地视频库找到成品 → 打开或分享。**

第一轮解决浏览骨架；第二轮解决“下载以后如何管理和找回”。两轮一起达到限定支持范围的 **0.1 本地产品版**，不宣称任意网站可下载。

本轮的主要增量是产品闭环，不是替换内核、增加协议覆盖或搭建后台服务。

## 2. 范围与边界

### 必须完成

- 将现有资源面板做成用户看得懂、可操作的资源中心。
- 下载中心按进行中、已完成、失败/需处理分组；正确展示等待、未知大小和格式初检状态。
- 公开直链的重新下载与返回来源页；给出过期、鉴权、格式错误的诚实提示。
- 本地视频库：仅管理本应用记录的成品，支持列表/搜索、真实元信息、打开、分享和记录/文件管理。
- 重启对账：从系统任务与文件实际可读性恢复状态，不把本地缓存当作永远有效。
- 默认仅 Wi-Fi 设置持久化；下载确认允许显式调整当前任务的网络选项。
- 原下载记录的安全迁移，不自动重下、删除或丢失原文件。
- 代码完成后，完成主路径、异常状态、老数据迁移与既有功能回归，交付 APK。

### 明确不扩展

自有账号/云存储/同步/解析/遥测，HLS/DASH 分片下载与封装，登录凭据转发，直播，内核替换，真正无痕，内嵌高级播放器，手动暂停/自定义断点续传，扫描全手机视频，任意目录选择，批量管理，物理文件重命名。

本轮可修改列表显示名称，**不把“改标题”伪装成物理文件改名**。播放器和分享使用用户主动调用的系统入口；分享不会由应用自动上传。
默认搜索引擎扩展、Cookie/缓存分类清理、完整真机矩阵仍保留在总规划，**不成为本轮下载闭环的前置条件**。

## 3. 现有代码约束与必要修正

核对位置：`app/src/main/java/com/example/purebrowser/`。

1. `DownloadRecord` 目前只有系统 ID 和文件名。原记录无法凭空获得媒体 URL、来源页、创建时间、UA 或网络偏好，因此不能直接许诺所有旧任务可重试。
2. `DownloadRepository.remove()` 当前调用系统删除接口，同时删除文件。新“移除记录”不能复用它；用户取消下载、移除记录和删除文件必须分开。
3. 成品初检目前只在进程内缓存；文件在外部删除后不能继续因旧 `verified=true` 显示为可播放。
4. 系统传输成功不等于视频可用；HTML 登录页、无视频轨文件、读取权限失效都必须有独立表现。
5. 当前文件保存在系统 Download 目录，以系统下载器提供的 URI 访问。本轮不改下载引擎、输出目录或权限归属，不依赖绝对文件路径操作。
6. 当前资源面板展示协议与证据，下载面板还混有权限/确认/打开操作。继续拆分职责，但不为本轮引入大型架构框架。
7. 浏览数据与下载数据分开；不为了新下载设置整体重写 T1–T7 的标签/书签数据结构。

- [ ] 建立“进行中 / 已完成 / 失败或需处理”分组，正确区分排队、正在传输、等待网络和系统重试。

- [ ] 公开直链失败允许显式重新下载：创建新的系统任务，保留旧失败记录并关联新记录，避免双击重复提交。
- [ ] 重新下载不是续传，不自动修改/补算签名，不转发凭据；401/403/过期提示优先返回来源网页重新发现。

- [ ] 重试不会隐式删除旧成品或其他任务；任务容量达到上限时给出整理入口，不静默截断记录。
- [ ] 完成通知仍由现有系统下载服务承担；应用再次打开即可对账，不为本轮增加常驻服务或长期后台处理框架。

建议位置：`ui/downloads/DownloadCenterScreen.kt`、`DownloadTaskDetail.kt`、`DownloadRepository.kt`、`BrowserViewModel.kt`。

**完成标准：**下载可观察；失败有下一步；新任务与旧失败可对应；关闭来源标签不影响任务；没有把失效链接重试包装成稳定成功能力。

## 5. 实现顺序与阶段成果

**T8 → T9 → T10 → T11 → T12 → T13 → T14。**

- A：记录迁移和资源中心，保留现有直链下载可用。
- B：下载分组、诚实失败与重新下载；能找到来源。
- C：本地视频库、打开/分享、记录/文件管理与必要设置；形成完整闭环。
- D：完成实现后的回归、覆盖安装/重启验收、APK 交付。

上面是开发依赖，不表示需要委派、新建聊天或停下来等待多个技术选型。继续以小规模本地代码推进，不虚报总工期。

## 6. 0.1 完成验收路径

1. 首页进入自建视频网页，资源卡片区分可尝试直链和未支持清单。
2. 调整建议文件名、确认网络选项并提交，任务中心显示真实进行中/等待/结果。
3. 关闭来源标签不取消任务；文件完成并通过初检后进入视频库。
4. 退出/强制停止后重新打开，在视频库找到同一成品并调用播放器/分享入口。
5. 从列表移除一条样本记录，验证文件仍在且重启不会重复入库；明确删除另一条成品，两个管理页面同步且文件确实不可再访问。
6. 用可控失败样本重新下载；过期/鉴权失败可返回来源网页，不冒充登录态能力。
7. 外部删除一份文件，列表展示丢失而非已可播放；无权限/无处理应用时仍能继续使用浏览器。
8. 覆盖安装旧版本数据仍可找回；默认 Wi-Fi 选项重启生效；第一轮浏览/标签/书签/历史/主题不回归。
9. 没有自有云端服务，没有不可用按钮伪装成已实现功能，关于页说明真实支持范围。

只有完成上述路径并记录证据，才将 T8–T14 勾选并将版本标为 0.1 已完成。APK 能启动或多几张页面截图不等于验收通过。

## 7. 风险与诚实降级

| 风险 | 本轮处理 |
|---|---|
| 旧记录只有 ID/名称 | 迁移可知字段，未知不伪造；没有 URL 就不能重试 |
| 系统已完成但返回 HTML/非视频 | 初检结果独立；不进入正常视频库，不自动删除文件 |
| 签名 URL 已过期 | 显式重新下载可能仍失败；指向来源重新发现，不补算签名 |
| 文件在外部删除/权限变化 | 实时可用性复核，失效与丢失分开；删除失败不假成功 |
| 系统传输状态不可读 | 展示无法确认而非凭缓存宣布成功；记录保留供处理 |
| 本地缩略图/时长解析失败 | 使用占位/未知，不阻塞主路径，不上云解析 |
| 记录与系统任务创建非同一事务 | 原子保存、提交失败明确反馈、必要时仅回滚本次新任务；禁止批量清理其他下载 |
| 任务默认设置被修改 | 只影响后续任务，当前任务采用提交时选项 |
| Share 启动后无回执 | 只说明已打开分享入口，不宣称接收方已收到 |

## 8. 后续轮次

第三轮：限定 HLS 点播子集、清晰度与必要音轨、分片/封装、登录访问上下文及逐跳凭据处理；使用已完成的 GitHub 调研材料，不重复无限找框架。
