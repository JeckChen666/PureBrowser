# PureBrowser v0.1.7（versionCode 16）

日期：2026-10-05。基线：v0.1.6/code15 同一长期证书覆盖升级。源码：`feat/v0.1.7`（tag `v0.1.7`）。

## 本版主题：站点规则层

- **内置站点规则层**：版本化规则数据文件（11 条规则：KVS/xplayer/html5player/flashvars 家族、Vimeo 配置端点、VK API 端点、Reddit 内联视频、通用播放器家族）＋受控解释器（动作白名单：DOM 提取/播放器配置/清单提示；≤50ms 预算、正则与体积上限、失败有界降级）。实现参考闭源竞品逆向分析（不指名）。
- **规则端点响应捕获**：仅对规则声明的 API 端点做只读响应体捕获（fetch clone/XHR responseText，256KiB 上限），解析出媒体地址与清晰度标签；去抖重评估（≤2 次/页）。
- **排序加权**：证据层内按"主片信号"（变体≥480p/体积区间/清晰度标签/播放中）加权，正片优先于预览。
- **YouTube 会话电池**（SESS）就绪：需在应用内人工登录后执行，本版未启用会话整合（R5 待补）。
- **诊断钩子**：冒烟测试支持 UA 覆盖。

## 实测证据

- 挑战站回归零倒退（S-A 四档全 VERIFIED、S-B master+3 档+39.9MB 直链）；规则层 S-C 站 309,105,790B MP4 端到端成品；339 项 JVM 单测、lint 零错误（[验收台账](../history/RELEASE-ACCEPTANCE-V0.1.7.md)、[验证证据](../history/V0.1.7-VALIDATION-EVIDENCE.md)）。
- 增强级：E1（31 分钟双轨长样本封装）、E2（15 分钟真实后台 219MB HLS）、E4（code13→code15 真实覆盖升级书签保留）通过；E3 API36 通过、API28 存在双轨发布路径产品缺口（登记 v0.1.8）。

## 已知边界（诚实声明）

- 部分规则站仅提供 AV1/fMP4 渲染（无 H.264 档），保存如实标注"不支持"；Vimeo/Reddit/VK 等受跨域 iframe 或登录墙限制，发现级可达、保存级不可达。
- YouTube 完整保存维持 v0.1.6 的匿名 No-go；会话路线证据待补测。DRM/凭据截获/远程规则下发不做。

## 安装

- `purebrowser-v0.1.7.apk`（附件），SHA256 见 Release 资产说明；与 v0.1.4–v0.1.6 同证书，可直接覆盖升级。
