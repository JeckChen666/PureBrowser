## 1. 版本定位：能力完整度——关闭已知死胡同 ＋ 规则规模化

> **没有新架构，全是兑现承诺与关闭议题：YouTube 终局、转写根因修复与规模化、HLS fMP4 音频接线、AV1 门控落地、FFmpeg 决策包。**

v0.2.0 的里程碑语义：v0.1.x 完成了能力面的搭建（通用分层→规则→主动提取→三种下载形态）；本版把散落各版"缓至 v0.2.0"的议题清偿，形成一个**边界清晰、无悬案**的能力完整度版本。

四条主线：

1. **YouTube 会话路线终局（T106）**：前置＝用户在应用内人工登录 YouTube → SESS 电池。Go → 基于 v0.1.8 会话铁轨（SessionOptIn／WebsiteAccessContext／凭据审计）做显式开关整合＋首个 YouTube 双轨有声成品；No-go → YouTube 从路线图移除，证据链闭环，专注其余站点。
2. **转写流水线根因修复＋规则规模化（T108/T109）**：两个已入档根因——顶层键指针启发式过简（改递归值遍历，融合 T64 PlayerConfigParser 思路）、hosts 白名单过严（新增"fetch host ⊆ 页面注册域 ∪ 规则显式声明域"的受控扩展，加载期校验不变）。修复后重跑批量验证，**必要级 ≥30 条实测成品入库**；长尾走签名导入。
3. **HLS fMP4 音频 rendition 接线（T107）**：把 v0.1.9 建成的 `Fmp4SegmentAssembler`（DASH 已复用）接到 HLS 独立音轨路径，处理 `EXT-X-MAP` BYTERANGE init。纯接线，解锁 arhiiv 类站点。
4. **AV1 运行时门控落地（T110）**＋**FFmpeg 决策包（T111）**：AV1 仅在设备具备解码器（`MediaCodecList` av01 查询，探针类已可复用）时展示可选并标注软解风险，API<29 隐藏；FFmpeg 做"格式缺口盘点"——fMP4/Media3 路径覆盖不了的形态清单为空则记录"永不引入"关闭议题，有硬缺口则出引入方案（许可/体积/停更风险）供用户拍板，**默认不引入**。

成功口径：三率分报、真实新增可用成品结账；新增判据含"会话整合成品（若 Go）""规模化新增 ≥30 站""HLS fMP4 音轨实站成品 ≥1"。

## 3. 能力层次与支持合同

- **YouTube 会话（若 Go）**：显式开关默认关、仅 youtube/googlevideo 域、逐跳校验、凭据不落盘；关闭路径行为与 v0.1.9 完全一致。
- **hosts 受控扩展**：规则 `fetch.hosts` 显式声明域，加载期校验 ⊆ 页面 host 的注册域 ∪ 声明域，仍禁 IP 字面量/私网；导入档规则不允许使用域扩展（内置特权）。
- **HLS fMP4 音频**：仅未加密、AV1 外的 fMP4 音频 rendition；与 TS 音频同预算同清理语义；EXT-X-MAP BYTERANGE init 以闭区间精确拉取。
- **AV1 门控**：无解码器设备的候选与档位隐藏（非置灰）；软解设备显示性能提示；成品校验含解码可用性。
- 沿用全部既有红线（纯本地、无 DRM/付费墙绕过、无远程下发、凭据不跨域、非开源竞品不指名）。
