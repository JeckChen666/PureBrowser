## 1. 版本定位：用户交互体验优化

> **三件事：LOGO 上线、下载链路简化到两步以内、把"给开发者看的话"全部换成"给用户看的话"。**

本版不新增任何嗅探/下载能力（v0.2.1 悬置规模化与 YouTube 等遗留议题，按用户 2026-10-07 指示）。现状基线（实测盘点）：

1. **LOGO 未使用**：启动器仍是模板图标；设计探索稿已有四方向（A 网页视频下载／B 下载即主角／C 播放转为保存／D 视频收纳）。
2. **下载链路过长**：以 HLS 为例，用户从资源面板到任务创建需 点开候选 →（可能"分析媒体"）→ 解析清单 → 选档位 → 准备 → 保存，**5–7 步**，且中途混有 wifi/会话/命名三组开关。而 v0.1.6 起"检出即解析"已把档位提前算好——链路长度是被 UI 流程拖住的，不是能力问题。
3. **提示语面向开发者**：实测 grep 可见"未加密的固定点播 MPEG-TS（H.264／AAC）""必须有可验证的强 ETag""此地址不是可交给受控下载器的 HTTP/HTTPS 文件直链""开发候选增加……"等，遍布资源面板、确认对话框与设置页"支持范围"整段规格语言。

## 2. 能力层次与支持合同

### A. LOGO 落地（T116）

- 用户从 A–D 四方向选定一个（D22）；按现有 `generate_logos.py` 管线出全密度位图（mipmap-mdpi…xxxhdpi）＋自适应图标（前景/背景/单色三层，含 Android 13 主题取色 monochrome）＋圆角版本。
- 落点：启动器图标、关于/设置页头部、分享与任务完成通知小图标（沿用同一矢量源，尺寸合规）；README 与 Release 品牌位同步替换。
- 设计源稿从本地 artifacts 摘录**成品位图/矢量**入 `docs/design/logo/`（批准参考入库，探索过程稿留本地）。

### B. 下载链路简化（T117）

**目标：默认路径 ≤2 步**（资源面板点开候选 → 点"保存"），全部智能化默认：

1. **单屏确认**：合并"解析清单→选档位→准备→保存"为一屏——默认档位已由检出即解析给出且高亮预选（1080p 及以下最优）；换档直接点选，无需"准备"按钮（准备折叠进保存动作的进度态）。
2. **智能默认**：wifi-only/会话开关按记忆值默认（首次默认：wifi-only 开、会话关闭）；文件名预填（标题/档位），一行可改。
3. **快捷路径**：候选卡长按/侧滑 → "用默认设置保存"（一步创建任务）；规则候选多格式时快捷路径取"最佳"格式。
4. **降级透明**：需要额外分析的 UNKNOWN 候选保留"分析"入口但不阻断主路径；失败原因在任务详情给**下一步建议**（见 C）。
5. 验收口径：真实站点（S-A/S-B/规则站各一）从打开视频页到任务创建 ≤2 次点击（默认档）；变更档位 +1 次；快捷路径 1 次。

### C. 提示语用户化（T118）

**原则：主文案只说"是什么、会怎样、下一步做什么"；协议与实现细节收进可折叠的"技术详情"。**

1. **全量字符串审计**：遍历 UI 层所有用户可见文案（资源面板/确认对话框/任务列表/失败原因/设置页），逐条分级——保留（用户语言）/改写/删除（对用户无行动价值）/折叠（技术详情）。
2. **失败原因→行动建议映射**：如"本版不支持加密 HLS"→"该视频受站点保护，暂无法保存"；"轨道地址失效或访问不足"→"链接已过期，请回到页面重新打开后再试"；"必须有可验证的强 ETag"→"该网站不支持断点续传，中断后需重新下载"。
3. **设置页"支持范围"重写**：规格段落改为用户视角的能力说明（"能保存什么/不能保存什么/为什么"），完整技术边界移入折叠详情与在线文档指引。
4. **术语替换表**（主文案层）：清单→播放地址；档位→清晰度；直链→视频文件；分轨→音视频分流；探测/验证→检查。代码/日志/诊断导出层保持术语不变（可诊断性不降级）。
5. 保留既有风格约束（冷灰＋蓝、触控目标、大字体、TalkBack 不回归）。

## 5. 安全与边界

- 本版不改嗅探/下载/规则核心逻辑；UI 合并流程只动展示与确认层，任务/凭据/预算语义零变化（对应测试保持全绿作为硬门槛）。

- 沿用全部红线与分级制度。
