## 1. 放行原则

- 首要目标是面对更多视频网站的通用抓取和实际保存增益，YouTube 是代表性核心样本，不是全部范围。
- 仅增加候选数、识别 blob、返回 URL、专用解析器或按钮都不算成品成功。只有 YouTube 改进、非 YouTube 没有新增成功不能放行。

## 3. M4 成品与成功率证据

样本与分母先冻结，不从新版本结果反选成功样本。每个有效配对的发现、方案、成品阶段分别记录，总体可用成品数增加且旧版受支持成功没有新版造成的倒退。站点变化保留原行并补足有效配对，不删失败抬高百分比。

- 建议至少 2 个 YouTube 作品（含官方 Sintel）及 6 个非 YouTube 作品／3 服务；同服务 CDN／子域、自制服务器、同作品不同画质不凑独立服务／作品。
- 至少两个独立非 YouTube 服务有新增成功；至少一个由通用层产生，不能全部来自网站专用解析器。
- 至少一个真实 YouTube 双轨成品；自制夹具不能替代。格式实际不可用如实披露，不猜 itag 或把单轨算有声成品。
- 成功样本必须实际保存、校验轨道／时长、首中尾声画观察、可播放及跨 UID 分享。URL、HEAD、少量字节、截图、容器初检单独都不算。
- 没有声音验证只算画面／元数据证据，需补音频观察。公开视频也需核验保存授权，不将登录可见当匿名成功。
- 报告逐行失败层、环境／hash、重试与耗时、改进来源；小样本不声称全网成功率，不预填 95% 等指标。

## 4. 系统、压力与分层验证

- 沿用现有 JUnit4／coroutines-test、Compose instrumented／Espresso 与主机工具；fake resolver／clock／网络和自制合法媒体验证可复现场景，不引入整套新测试框架凑规模。
- 使用专用 API28／36／37 设备，记录 WebView、访问环境、操作和清理。不得清个人应用数据或在个人浏览档案中做故障。
- 公网旅程与 CI 分离；CI 不依赖真实视频网站可用性。真实站点证据单独作为发行门槛，不能全部替换成夹具。
- ≥15 分钟后台测试是真实传输字节／FGS／网络策略的有声双轨任务，不用页面静置凑时间。>30 分钟压力用实际自制样本，不只改 duration 元数据，也不要求向公网反复抓长视频。
- 新公共引擎／生命周期变更必须重跑受影响旧直链／HLS 及恢复；旧 UI 版证据只用于基线，不能不经适用性判断继承。
- 升级保留旧包／种子／hash／前后结果，不以卸载重装代替覆盖，不改写旧报告输入。精确最终包再做当前非 YouTube 增益和 YouTube 成品烟测。
