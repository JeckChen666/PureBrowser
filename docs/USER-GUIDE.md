# PureBrowser 使用说明（v0.1.3 候选）

## 安装与升级

最低 Android 8.0 / API26。正式包 io.github.jeckchen666.purebrowser，Debug为独立.debug包。
从v0.1.1沿同包同证书升级，不卸载旧包；安装失败先核对版本Code与签名，不通过卸载来掩盖数据丢失。
原v0.1.0 com.example.purebrowser保留，不自动迁移私有数据或网站会话。
当前是0.1.3-rc.1候选，不是正式v0.1.3发行；v0.1.2也仍有真实验收门槛。

## 保存视频

打开获授权网页→资源中心→选择资源→核对来源、格式、档位、网站访问条件及Wi-Fi选项→确认下载。
Cookie仅在限定同源条件下即时读取，不保存到下载记录；关闭访问条件不会提取私有Token或绕过授权。
MP4/WebM直链及无后缀可确认视频可尝试保存。HLS仅支持结束、未加密、单节目MPEG-TS/H.264+同组AAC。
直播、加密、DASH、独立音轨、fMP4/BYTERANGE、复杂跨站鉴权等不支持。能播放不代表能保存。
成品通过初检并完成公共发布后，才显示“已保存”；分片100%不是成品完成。

## 暂停、继续与重新下载

- 支持条件的直链：先形成可信检查点，才开放暂停；继续必须得到与原资源一致的206范围响应。
- HLS：保留有长度/SHA-256检查点的完整分片；半片不续写。继续核对原清单，拒绝换档位/换清单混拼。
- 正在暂停：等待旧写入线程结束，不连续点击继续。封装/校验/公共发布不提供假暂停。
- 取消：结束任务、清理本任务恢复缓存。重新下载：新建任务，不是原任务续传。
- 服务器不支持Range、链接或会话失效、资源变化：说明原因，请返回来源或另建下载；不静默从头覆盖进度。
- 历史系统DownloadManager任务不承诺手动暂停。

## 后台与恢复

下载使用前台服务和本地通知；通知拒绝时仍可返回应用查看，不保证所有设备后台行为一致。
当前会话中可在条件满足时恢复网络等待；所有任务都等待时结束前台服务，返回应用重新检查。
进程死亡、强停、重启后先对账，再由用户主动继续；不承诺强停后运行或开机自动下载。
封装中断后从完整分片重新封装。系统限制、存储不足可能要求恢复条件后重新操作。

## 文件与清理

成品在公共 Download/PureBrowser。API26–28需要旧版存储权限；新系统走MediaStore。
视频库“移除记录”保留公共文件；“删除文件”明确确认并验证归属。外部删掉的文件不能假装可播放。
应用私有恢复缓存不等于成品；清理停止任务缓存后，相关任务只能重新下载。
隐私设置分别处理历史、网站数据、网页缓存、停止任务恢复缓存。不会隐式删除成品或书签。
网站数据/网页缓存清理会关闭活动网页并停止应用自管下载；不可靠续传的进度可能丢失。
标签地址保留，需主动重新打开。历史系统下载仍由系统管理，网站会话清理不接管其状态。
旧版WebView接口缺少完整清理完成证明，界面会显示“已请求清理”，不承诺完整单站点/所有存储技术抹除。

## 诊断与问题反馈

设置中主动生成脱敏诊断→预览→选择是否分享。报告无地址、Cookie、鉴权头、文件名、标题或任务稳定ID。
不自动上传。反馈可附版本/系统/WebView、操作步骤和非敏感错误；不要粘贴登录Cookie或签名下载地址。
只保存自己拥有、开放许可或明确获授权的视频；不得用于绕过DRM、付费访问或其他访问控制。
