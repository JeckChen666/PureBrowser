# PureBrowser 总体规划

日期：2026-10-01（Asia/Shanghai）
状态：建议方案；协议覆盖、内核选择及发行渠道尚未最终确认。
本次只规划，不改变现有应用代码或依赖。

## 1. 产品定位

做一个“为了保存网页视频而设计的轻量浏览器”，而不是先做通用浏览器再添加下载按钮。
核心闭环：打开网页 → 按需播放 → 发现视频候选 → 确认清晰度与访问条件 → 下载 → 得到可播放文件。

产品优势应落在以下四件事：

1. 在合理权限和技术边界内，发现更多真实媒体资源。
2. 把重复请求、分片、不同清晰度聚合成用户能理解的视频条目。
3. 在必要且可取得的访问上下文中可靠下载，而不是只复制一个地址。
4. 准确解释“没发现”“已过期”“需要重新登录”“受保护”“不支持的格式”等不同结果。

首版建议本地运行、无账号和无后端；不上传浏览历史、网页内容或登录凭据。
可下载不等于用户拥有复制权；仅面向自有或获得授权的内容，不绕过 DRM、付费或登录访问控制。

## 2. 体验设计

### 浏览主界面

地址/搜索栏、前进后退、刷新、标签页、下载中心入口；发现候选后出现带数量的资源按钮。
嗅探按当前标签页及导航代次归属，不能把上一页资源误挂到当前页面。

### 资源面板

默认展示按视频聚合的卡片，而不是数百条 .ts 请求：

- 标题/封面：只展示可靠取得的信息，缺失时使用中性占位。
- 清晰度、码率、时长、容器、音轨、文件大小：未知就是未知，不编造估计值。
- 状态：待确认、可下载、需要重新打开页面、已过期、暂不支持、受保护。
- 操作：选择清晰度、预览、下载、查看详情、在用户确认敏感性后复制地址。

保留高级原始资源视图用于排障，但不是默认体验。
没有资源时引导用户播放视频后重试，不宣称任何页面都能立即嗅探。

### 下载中心

进度、速度、剩余量（可计算时）、暂停/继续、取消、错误原因、打开、分享、清理临时文件。
关闭标签页不等于取消下载；用户从系统任务管理器停止应用后，不保证自动恢复执行。

## 3. 覆盖范围

| 能力 | 建议阶段 | 边界 |
|---|---|---|
| MP4 / WebM 直链 | MVP-A | 实际类型验证；服务器支持 Range 才承诺断点续传 |
| 无扩展名地址、重定向、适用 Cookie/Referer 的直链 | MVP-A | 不能承诺重建所有浏览器内部请求条件 |
| 明文 HLS 点播 | MVP-B，正式 v1 前完成 | 从有限子集开始，明示是否支持主清单、独立音轨、TS、fMP4、byte-range、discontinuity |
| DASH 点播、音视频分离 | v1 后增强 | 必须先证明下载与封装路径 |
| blob / MediaSource 播放 | 增强 | 尝试关联底层请求和清单；不把 blob 当普通 HTTP 下载地址 |
| Service Worker、跨域 iframe 复杂场景 | PoC 建立覆盖表，后续增强 | 各观测渠道都有边界，不能宣称无遗漏 |
| 普通加密 HLS | 后续单独评估 | 不与 DRM 混为一谈；需合法可访问密钥并验证算法与密钥轮换 |
| DRM、付费/授权绕过 | 不做 | 展示受保护/不支持，不提供破解 |
| 直播录制、自动整站批量下载 | 不做首版 | 磁盘、时长、配额和中断语义需另立方案 |
| 跨设备同步、扩展市场、VPN/MITM 抓包 | 不做首版 | 避免偏离视频保存闭环 |

建议正式 v1 至少完成直链和明确范围的 HLS 点播；只有直链的版本作为内部验证版本。

## 4. 技术路线与观测边界

### 内核

先用系统 WebView 做最小验证，但不把最终选择写死。
如果关键目标场景无法观测，先做 GeckoView 对照验证，再根据覆盖、兼容性、体积和维护成本决策。
不要仅因为可替换内核就宣称更强嗅探；需要同一套样本上的实测。
不自编译完整 Chromium，不将系统 WebView 等同于支持 Chrome 扩展的完整 Chrome 浏览器。

官方 WebView 文档说明，shouldInterceptRequest 不是完整响应抓包接口：

- 能观测资源请求并允许自定义返回；返回 null 时仍由 WebView 加载。
- 不调用 blob: / javascript: URL 的此回调。
- 重定向只保证最初资源地址的回调，而不是完整重定向链。

因此先采取被动、非阻塞观测，不把所有页面流量改为应用自己的 HTTP 请求。
WebView callback 不提供默认加载结果的通用响应体监听；响应 MIME、长度和封装信息需从可取得的其他证据或受限探测获得。

### 多渠道线索

1. WebView 资源请求与下载回调。
2. DOM 的 video/source 元素及动态变化，优先采用最小的只读采集方式。
3. 可用的 ServiceWorkerClient 请求观测，建立导航关联和覆盖限制。
4. 受控的资源验证：优先利用已有证据，必要时限量探测；不对每条请求自动完整重下载。
5. 后续才评估兼容性风险较高的 fetch/XHR/MediaSource 辅助观测。

所有网页输出均视为不可信数据。页面不能通过采集接口直接发起后台下载、读取凭据或操作文件。

### 媒体解析

判断证据：URL 提示、可取得的 MIME、清单格式、有限文件头、DOM/播放关联。
不依赖扩展名；请求出现不代表资源一定可下载。

去重必须保留签名参数和访问条件；不能简单删除 query 字符串。
聚合需区分视频、音轨、清晰度、时间线与分片，避免把不同视频混合。
链接验证不得无限重试或消耗大量流量，尤其要考虑短期/一次性签名。

### 下载与文件输出

- 渐进式文件：流式写入、可控并发、取消、超时、重试及 Range 验证。
- 续传：检查 206 / Content-Range、ETag 或 Last-Modified；服务器返回完整文件时不得直接追加旧文件。
- HLS：解析主/媒体清单，选择清晰度及音轨，保存分片清单和进度；缺失片段不能标为完成。
- 封装：先判断输入协议、容器、编解码器和时间戳是否支持，再选择 remux 或明确拒绝；首版不做默认转码。
- 预览：评估 Media3。其离线下载 Cache 不等于可直接交付的 MP4；下载缓存、导出文件和重封装分开设计。
- 完成校验：验证容器、时长及声画可播放性；不能因下载到了 HTML 登录页就宣告成功。

选择 FFmpeg/native 方案前，必须完成体积、许可证、ABI、16 KB 页大小及维护成本评估；不能为简单直链预先引入巨大原生依赖。

### 后台执行

Android 14+ 长时间用户触发的下载优先评估 UIDT JobScheduler。
较低版本评估 WorkManager 前台执行或专用前台服务，并遵守各系统版本启动规则。
WorkManager 用于短小可中断任务、维护和重试，不把所有长视频任务无条件塞入同一策略。
Android 15+ dataSync/mediaProcessing 前台服务存在后台时长限制，不能把前台服务当无限运行保证。

任务记录与传输器分离；暂停、网络变化、系统终止时保存一致进度，应用重新打开后进行恢复判断。
用户主动停止的任务不得违背用户意愿自动重新启动。

### 存储与安全

- 私有目录保存分片和未完成文件；校验完成后才公开下载成品。
- Android 10+ 评估 MediaStore；低版本或用户自选目录使用 SAF，避免默认申请所有文件访问。
- Cookie/Authorization 等只按适用站点和用户会话传递，跨域重定向不得无条件转发。
- URL、Cookie、签名和网页内容不写入普通生产日志；如必须持久化敏感上下文，应最小化、加密并排除备份。
- 不向任意网页暴露通用 addJavascriptInterface；采集消息校验来源、大小与结构。
- 证书错误不静默放行，生产版不启用 WebView 远程调试。
- 无痕模式必须真的隔离 Cookie/缓存，不能只是不记录历史；未验证隔离前不提供虚假的无痕承诺。
- 明确说明版权和下载授权边界；Google Play 对鼓励未授权复制有明确限制，发行前检查政策及法律风险。

## 5. 架构

先保留一个 app 模块，用包和少量接口分隔职责，避免提前多模块化：

浏览器/会话 → 资源观测 → 候选识别与聚合 → 媒体解析 → 下载方案 → 执行与恢复 → 封装校验 → 文件库

建议边界：BrowserEngine、ResourceObserver、MediaResolver、DownloadExecutor。
建议组件：Compose/Material 3、WebView/AndroidX WebKit、协程/Flow、OkHttp、Room、DataStore、按需 Media3。
具体依赖版本在实现前根据现有 AGP/Kotlin 和 SDK 验证，不因规划直接全量升级。

浏览器负责会话；资源层负责候选；下载层负责用户已确认的任务。
核心领域词汇见根目录 CONTEXT.md，不把网络请求、视频候选和下载任务混为一类。

## 6. 开发顺序（按用户于 2026-10-01 的要求调整）

先完成基础程序代码，再针对已实现代码做构建、测试和迭代；不先做一轮孤立 PoC 来阻塞基础程序。
资源嗅探的核心实现必须同时查阅 GitHub 相关源码，调研记录见 SOURCE-RESEARCH.md。

### 第一阶段：基础浏览器代码

单 WebView 浏览、地址与搜索、前进后退刷新、首页、媒体候选面板、公开直链的系统下载、任务记录及格式初检。
资源观测先覆盖 WebView 请求、页面视频元素、Resource Timing 和下载回调。
HLS / DASH / blob 显示候选与限制，不虚构复杂格式下载能力；多标签、独立登录态下载和自定义后台传输器后续实现。

代码完成后才执行单元测试、Compose 仪器测试和自建视频样本的下载闭环测试。

### 第二阶段：扩展核心能力

根据现有代码和失败样本补充 MIME 验证、登录访问上下文、HLS 清晰度 / 分片 / 恢复与封装。
对实际覆盖缺口进行内核对照评估，而不是在没有基础实现时预先更换内核。

### 第三阶段：增强与发布

DASH、复杂播放器、多标签、实际隐私隔离、真机后台与网络变化测试、完整成品校验、性能、安全、包名与发行方案。
只有公开直链的当前基础版本，不等同于正式资源嗅探浏览器 v1。

## 7. 测试矩阵

- 识别：无后缀/错误 MIME、重复 URL、同视频多清晰度、广告、导航切换、iframe、Service Worker。
- 协议：HLS 相对路径、主清单、缺失分片、init segment、byte-range、discontinuity、音视频分离。
- 访问：Cookie/Referer、301/302、短期签名、过期、401/403、登录页、跨域凭据泄漏。
- 恢复：断网、网络切换、进程被系统终止、用户主动停止、续传校验、磁盘不足。
- 输出：哈希或时长、容器可解析、声画一致、成品可由外部播放器打开。
- 设备：围绕 minSdk 26、存储分界 API 29、UIDT 分界 API 34、当前新系统和不同 WebView 版本；至少补一台真机验证后台行为。
- 安全：恶意页面伪造采集消息、路径穿越、超大清单、日志泄密、证书失败。

验收看协议矩阵覆盖率、误报、成品可播放率及中断恢复正确性；不以“发现多少条 URL”作为成功指标。

## 8. 当前建议与待确认

当前按用户要求先实现基础浏览器代码，完成后测试，再逐步扩展嗅探和下载范围；不先做账号、云服务或复杂浏览器设置。
默认假设：中文优先、Android 8.0+、手机优先、本地优先、用户主动选择下载。
待确认：最常用的 3–5 类页面/站点、正式 v1 的 HLS 子集、发行渠道、正式包名。
上面的默认假设和阶段范围不是用户已经批准的产品规格。
