# V0.1.9 T102 AV1 解码探针结论（D14）

日期：2026-10-05。方法：`AV1DecodeProbe`（androidTest，仅能力查询——按冻结计划，手工编写合法 AV1 基本流不可行，探针止步于 MediaCodecList 能力问题）。运行环境：本实验室断网边界内仅有的两台模拟器（无真机——结论按此诚实限定）。

## 探针数据

| 设备 | av01 解码器数 | 明细 |
| --- | --- | --- |
| PureBrowser_API37_ReleaseLab（API 37 模拟器） | 2 | `c2.android.av1-dav1d.decoder`（软件）、`c2.android.av1.decoder`（软件）；均 2–2048 宽/高、1–40 Mbps；**无硬件解码器** |
| PureBrowser_API28_Test（API 28 模拟器） | 0 | 平台不含任何 av01 解码器（`anyDecoder=false`） |

## 结论：**推迟（defer 到 v0.2.0，不做本版排期）**——按 D14“有解才排实现”的门槛未过

理由：

1. **播放覆盖是产品门槛而非“存在解码器”**：本应用最低支持到 API 26–28 机型段，而 API 28 平台零 AV1 解码能力。若本版开放 AV1 档 DASH 下载，minSdk 段用户将得到无法播放的成品文件——违反“不发布半个输出/诚实失败”的红线精神。
2. **唯一可用解码是软件实现**：API 37 上仅 `c2.android.av1*` 软件解码（≤2048p、≤40 Mbps），模拟器环境无硬件 AV1 证据；软解高分辨率实时播放的性能在本实验室内无真机可测。
3. **下载路径本身不需解码**（fMP4 组装为再封装），因此推迟不阻塞 T96/T97 的 H.264 档 DASH 能力；AV1 仅是格式覆盖扩展。

## 复评条件（进入 v0.2.0 排期的门槛）

- 实验室纳入具备硬件 AV1 解码的真机并跑通 `AV1DecodeProbe`（本探针类可直接复用为运行时能力门控：按 `MediaCodecList` 查询 av01 硬件解码器存在性，再决定档位是否展示）；或
- 引入“设备能力门控＋如实标注”设计（无解设备隐藏/标注 AV1 档），且经产品决策接受软解性能风险。
