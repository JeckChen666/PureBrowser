# T112 QuickJS 触发条件实测统计与评估（D21）

日期：2026-10-06（Asia/Shanghai）。分支 `feat/v0.2.0`。本文件只做统计与决策建议，**不实现 QuickJS**（D21 明确：统计先行，门槛成立才立项）。

数据来源（全部离线既有产出，无新增网络请求）：

- `tools/rules-transcriber/output/classification.csv` — yt-dlp 2026.08.19（固定版本）2020 个提取器类的逐条分类；
- `tools/rules-transcriber/output/rejected.json` — 1956 条结构化拒绝的逐条理由；
- `tools/rules-transcriber/output/candidates.json` — 64 条通过装载校验的 v3 候选及其审查主题；
- `docs/history/V0.1.9-T100-RULES-EVIDENCE.md` — 迄今唯一一批实站验证（19 站）的逐站根因记录。

红线遵守：语料中的成人站条目只计数、不点名；本文件不出现其名称或地址。

## 1. 口径（D11/D21 触发条件的操作化）

D11（v0.1.8 冻结）触发条件任一成立才另版启动：

1. **① 规模化中 ≥3 个目标站因"地址须执行站点 JS 才能得出"而无法出格式** —— 关键词是"实测受阻"：要数的是**本产品管线内被 JS 挡住的站**，不是上游语料里"用了 JS"的站。上游 JS_COMPLEX 类只是必要不充分的上界（有 JS 痕迹 ≠ 本产品被它挡住 ≠ QuickJS 能解）。
2. ② 产品决定提供"不开页面直接提取"模式 —— 产品决策项，未启动。
3. ③ 站点 JS 计算地址成为主要形态 —— 需占比证据。

v0.2.0 D21 复述同一门槛（"≥3 才立项本版"），本文件按 ① 的操作化口径给出计数。

## 2. 计数

### 2.1 上游语料（上界，非"受阻站"计数）

| 层级 | 条数 | 占 2020 类比例 | 说明 |
| --- | --- | --- | --- |
| JS_COMPLEX（宽口径） | 325 | 16.1% | 含 multiple download calls（132）、`_real_extract` 超 60 行（119）等复杂度启发，多数并非"地址须执行 JS" |
| challenge/signature tokens（窄口径，下称"JS 痕迹 cohort"） | 61 | 3.0% | 60 条带 test_url；token 分布：`js_to_json` 55、`player_json` 2、decrypt 族（xor/文件名/m3u8 解密）4、`_handle_vuejs_page` 1（有组合重叠，合计 61） |

窄口径内的 55 条 `js_to_json` 是"把页面里的 JS 对象字面量转成 JSON 再取键"——多数可用**容错字面量解析**（远小于 JS 运行时的能力）覆盖，并非必须执行站点 JS；真正"须执行站点 JS/站点加密代码"的 decrypt 族＋vue 处理仅 **5 条**。

结构侧交叉验证：325 条 JS_COMPLEX **全部**被转写器结构性拒绝（rejected.json 中 JS_COMPLEX 前缀 325 条），成为 v3 候选的 **0 条**；64 条候选全部来自 SIMPLE/POST_API，候选审查主题（json pointer 启发 37、默认 url 指针 24 等）中没有任何"需执行 JS"类目。

### 2.2 本产品实站受阻计数（D11① 的分子）

T100 实测 19 站（每站 1 次＋至多 2 次重试；3 站成功，16 站如实失败）的全部失败根因分布：

| 根因 | 站数 | QuickJS 是否能解 |
| --- | --- | --- |
| HlsResolver 拒绝独立音轨形态（产品级缺口） | 4 | 否 |
| 直播流无可下载档位 | 1 | 否 |
| 规则指针解析为非字符串容器（数组/对象，schema 演进项） | 4 | 否（T100 已登记指针深挖/数组遍历） |
| 页面改版/正则无匹配 | 1 | 否 |
| 模板不匹配或需 POST/鉴权 | 6 | 否（需 POST/凭据能力，非 JS） |
| **地址须执行站点 JS 才能得出** | **0** | — |

另：T100 未实测的候选里也没有任何一条的未测理由与 JS 相关（未测主因是登录墙/403/地域封锁/改版/纯音频）。

## 3. 门槛判定

- **①：0/16，未达 ≥3**。这是唯一一批按站记录根因的实测数据，如实计数为**零**。
- **②：未触发**（无"不开页面直接提取"的产品决策）。
- **③：未触发**。语料宽口径 16.1%、窄口径 3.0%，均非主要形态；且本产品主发现通道是真实 WebView 页面播放时的网络请求观测——**页面 JS 已由 WebView 执行**，JS 计算的地址在主通道里已自然物化为请求。QuickJS 只服务"无页面规则取回"这一条 D11② 尚未决策的旁路。

**结论：门槛未满足（honest verdict）。** 任务预期"很可能达标"来自 325 这个宽口径数字；按 D11① 的实测口径它不成立——325 是上游复杂度分类，不是本产品受阻计数，二者不应混同。

## 4. 若触发的范围估计（不立项也要留档）

- 窄口径 61 站池（非成人、可点名的主流示例：BBC、CBC、CSpan、SVTPlay、TVP、TubiTv、Udemy、YoukuShow、XiaoHongShu、Imgur、Mixcloud、Nova、SteamCommunity、Substack、Brightcove 嵌入族；另有 1 条成人站条目仅计数不点名）。多数公共台站（BBC/CBC/SVT 一类）命中的是 `js_to_json` 配置解析，不是签名挑战。
- 其中 QuickJS **单独**即可解锁的估计只有 decrypt 族＋vue 一类，约 5 条上游形态，且部分还叠加 POST/鉴权/DRM 前置条件（QuickJS 不解决这些）。
- 55 条 `js_to_json` 形态的更优解是容错 JS 字面量→JSON 解析器（纯 Kotlin、无新依赖风险），或 T100 已登记的指针深挖/数组遍历 schema 演进——两者都应先于 QuickJS 评估。
- 成本侧（沿 v0.1.8 盘点）：静态库约 0.5–1 MB、MIT 许可、独立安全审查与沙箱边界（规则数据驱动执行第三方脚本的攻击面）。

## 5. 建议

**不立项（本版不引入 QuickJS）**，D11 继续作为后置规划项。配套两条低成本动作：

1. T108 规模化批次的逐站根因表固定增加"须执行站点 JS"一栏（零代码，仅记录口径），下批实测若 ≥3 站命中即按 D11① 触发另版立项评审；
2. 把"容错 JS 字面量解析"与"指针深挖/数组遍历"作为 QuickJS 的前置替代项排入 schema 演进评估——它们覆盖窄口径池的大多数，且无新依赖与沙箱风险。
