# PureBrowser 产品化规划

更新日期：2026-10-01（Asia/Shanghai）
状态：T1–T14 已完成，限定支持范围的 0.1.0 本地产品预览版已验收。第一轮证据见 T1-T7-COMPLETION.md；第二轮见 ROUND-2-COMPLETION.md。
第一轮已完成清单见 EXECUTION-PLAN.md；第二轮 T8–T14 见 EXECUTION-PLAN-ROUND-2.md（T8–T14 已完成）；增量实绩见 ROUND-2-STATUS.md。
当前应用能力与测试实绩以 IMPLEMENTATION-STATUS.md 为准。

## 1. 本次明确的方向

用户明确要求：不增加云端存储或自有云端服务；希望尽快出现可日常使用的产品形态。
因此近期优先级由“继续深化协议覆盖”改为“把已有浏览、嗅探和直链下载做成完整产品体验”。

产品定位：纯本地、以网页视频发现和保存为核心的 Android 浏览器。
近期交付：0.1 产品版——功能范围有限，但所承诺的浏览、资源发现、文件保存与管理是完整可用的。
不是完成所有格式后才做产品，也不是只换皮肤就把 demo 宣称为成熟浏览器。

## 2. 不可变的产品边界

### 明确不做

- 自有后端、云端存储、网盘、浏览记录或文件云同步。
- 应用账号、注册登录、会员体系及相应账号服务器。
- 云端视频解析、把网页/视频链接上传给远程解析服务。
- 远程用户行为追踪、云端日志收集或自建内容推荐服务。

下载成品、标签页、书签、历史、设置和任务记录均保存在设备本地。
用户仍可以正常访问网页、搜索引擎和网站账户；“纯本地”不等于“不能联网”。
网站登录是访问该网站的会话，不是 PureBrowser 自身的账号体系。
站点图标优先使用浏览时取得的本地缓存或占位图，不接入第三方图标云服务。

### 不做虚假承诺

不绕过 DRM 或访问控制；不宣称任意网站都能下载。
无痕隔离未真正完成前不提供只隐藏历史的“无痕模式”。
没有实现的 HLS 合并、手动暂停、任意存储目录等，不出现在主界面作为可点击的假操作。

## 3. 当前离“产品”还有哪些差距

已有：正式首页、多标签、地址与搜索、导航、本地书签历史与快捷站点、统一浅深色主题、最小设置、媒体候选、公开直链下载、任务记录与有限格式初检。
第二轮资源中心、下载中心、本地视频库与文件操作已完成。当前缺口是 HLS/DASH 分片/封装、必要登录访问上下文、长任务/真机矩阵及正式发行准备。

本轮不再优先新增更多协议、替换内核、引入大 SDK、扩大技术调研或搭建复杂测试平台。
资源嗅探仍是主入口；需要产品化已有能力，而不是把它藏起来或做成普通浏览器的附属开关。

## 4. 0.1 产品版的信息架构

### A. 首页 / 新标签页

- 应用名称与统一图标、清晰的地址/搜索入口。
- 本地常用站点快捷方式：添加、编辑、删除，缺少图标时使用一致占位。
- 书签入口、最近浏览、本地最近下载入口。
- 空白状态以引导首次操作为目的，而不是长篇技术说明。
- 删除“当前基础版”“暂不支持协议清单”等开发说明卡片；版本能力放在关于或对应资源详情。
- 初次启动不要求账号、不加载应用自己的推荐内容接口。

### B. 浏览页面与多标签

- 聚焦、粘贴、提交、取消地址编辑的行为一致，键盘与系统返回不打架。
- 加载进度、停止加载、刷新、清晰的网络错误和重试入口。
- 新建、切换、关闭标签；支持在新标签中打开普通网页链接。
- 每个标签的当前网址、标题、前进后退及媒体候选独立，不串页。
- 本地保存标签列表及选中标签；重启能恢复网址，不假装恢复未提交表单或所有网页内部状态。
- 控制活跃页面资源占用，不为每个历史标签无限保留运行中的网页。
- 关闭标签与取消已经确认的下载任务是两件事。

### C. 资源中心——核心功能的产品入口

- 浏览时保留明显的资源入口和数量提示，不只放在菜单里。
- 默认优先展示页面视频元素关联的候选，以及本版可尝试保存的直链。
- 卡片显示可理解的名称、类型、来源、可靠取得的大小；未知就标为未知。
- 操作先做“尝试下载”“返回来源页/详情”，不暴露一长串碎片地址。
- 原始 URL、证据来源、协议细节放在详情中；带签名 query 不在普通列表公开展示。
- HLS / DASH / blob 等未支持项保留在可展开的“其他媒体资源”分区，明确说明限制；不删除证据，也不让满屏灰色按钮成为默认体验。
- 不能确认访问条件时使用“可尝试保存”，不能把 URL 后缀识别当成下载成功保证。
- 无资源、过期、需要登录、不支持格式、下载失败分别提供有意义的提示。

### D. 下载中心与本地视频库

- 下载中心：进行中、已完成、失败三个清晰分组。
- 进行中：已传输量、可靠取得的总量、等待原因、取消。
- 失败：可理解原因、返回来源页、重试；重试若重新开始必须说明，不伪装成断点续传。
- 已完成：本地名称、大小、可靠取得的时长/缩略图、打开、分享、重命名（在权限及文件能力允许时）。
- 本地视频库只围绕本应用保存的文件，不默认全盘扫描用户手机。
- 任务记录和本地成品分开：“删除记录”不等于“删除文件”；删文件需要确认。
- 文件被用户移走或删除时，清楚标记失效，不展示永远有效的“打开”按钮。
- 保存目录和是否允许移动网络有明确说明；当前不能支持任意 SAF 目录时只显示真实的默认目录，不提供假的目录选择器。
- 内嵌播放器可以后置；0.1 至少能调用系统播放器和系统分享。

### E. 书签与历史

- 从当前页面添加、取消书签，首页有稳定入口。
- 书签列表、搜索、编辑名称/网址、删除；复杂文件夹与导入导出后置。
- 历史按时间显示，支持搜索、单条删除和清空。
- 清理历史不默认删除书签、已下载视频或网站登录状态。
- 浏览数据仅本地保存；清除 Cookie 时提示会影响网站登录。

### F. 必要设置与关于

只做真实有用、已经能执行的选项：

- 浅色/深色/跟随系统。
- 默认搜索引擎（直接访问所选搜索服务，不经过自有服务器）。
- 下载是否仅 Wi-Fi、保存位置说明。
- 分类清除历史、缓存、Cookie；不误删下载文件。
- 版本、隐私说明、当前下载支持范围、开源声明。

不放账号、云同步、会员、云解析入口；不堆放尚未实现的“高级能力”开关。

## 5. 视觉与交互标准

方向：简洁、克制、工具感，以浏览内容和保存操作为主。

- 统一图标、主色、字号、间距、卡片、按钮、错误反馈和深浅色。
- 主操作明确：打开网页 → 发现资源 → 保存，不同时摆一排同等权重按钮。
- 首页、浏览、标签管理、资源、下载、视频库、书签历史、设置使用一致导航和返回规则。
- 空状态、加载、权限被拒绝、失败、成功都必须有完整表现。
- 页面开发术语与内部错误编号不直接充当用户文案。
- 不制造虚假的封面、清晰度、时长、百分比和可下载状态。
- 小屏和键盘弹出时主要操作仍可访问；删除、清理、取消有适当确认。

产品化不是盲目增加动画和复杂组件；先让每个页面都能完成真实任务。

## 6. 执行顺序与交付物

### 第一批（T1–T7 已完成）：产品骨架与浏览体验（近期最高优先级）

统一视觉和应用标识；重做首页；梳理地址/键盘/返回；建立标签页管理和本地恢复；加入书签与历史。

交付：可以日常打开网页、切换多个页面、收藏和找回页面的 APK；不再以功能说明页作为首页。

### 第二批（T8–T14 已完成）：现有嗅探和下载的产品化

资源入口与卡片重做；可支持项与待支持项分区；下载分组、失败/重试、成品索引、打开/分享、必要文件管理。
完善设置、权限说明、错误和空状态。

交付：本版支持范围内，用户能从浏览走到本地文件，并在之后找回该文件；不能只展示 URL 列表。

第一、第二批合起来才叫“0.1 产品版”。只完成漂亮首页不算完成，不能把下载闭环留成占位。

### 第三批：核心能力增强（紧随产品版，但不阻塞前两批）

明确定义的 HLS 点播子集；清晰度、分片、封装；必要的登录访问上下文；逐跳凭据处理。
基于实际使用的失败样本改进识别，必要时才对照其他内核。

GitHub 源码调研已经有材料，不先继续无限扩散找框架；在实现相应能力时使用相关参考。

### 第四批：覆盖与发布质量

DASH、复杂 iframe / Service Worker / MSE、更多 HLS 组合、大文件/长时间后台、真机矩阵、性能与安全深测、发行渠道。
不把上述每一项都完成作为第一份产品 APK 的前置条件。

不虚报总工期；按可安装、可操作的版本交付，而不是以新增多少接口或测试项目作为进度。

## 7. 测试安排

尊重“先有完整基础代码，再测试”的开发顺序：每一批先完成相应代码与页面，再构建和验证。

近期不优先扩大测试基础设施，但不能延后阻断性错误检查：

- 应用能启动，所有可见按钮有实际行为，没有导航死路。
- 新建/切换/关闭标签不串资源、不误取消下载。
- 支持的直链可以保存，下载成品可以找回、打开、分享。
- 重启后标签、书签、历史、设置、任务索引正确；文件缺失时处理正确。
- 键盘、返回、删除确认、权限拒绝、网络失败不会造成崩溃或无法继续使用。

广泛网站/协议兼容性、长视频后台矩阵、系统多版本深测、模糊测试和性能专项排到后面。
既有单元测试与本地视频样本继续用于防回归，不因产品优先而删除或忽略已知错误。

## 8. 0.1 完成标准

必须真实完成以下一条日常使用路径：

1. 从首页进入网站，打开第二个标签，切换和关闭标签行为正常。
2. 将页面加入书签，查看历史，关闭并重启后仍能找回。
3. 在一个受支持且获授权的视频页面发现媒体，完成明确的下载操作。
4. 关闭来源标签后，任务和已完成文件仍有独立管理入口。
5. 在视频库找到成品并调用播放器/分享；文件被删后有清楚状态。
6. 修改主题或下载网络选项，重启后生效；清理历史不误删视频。
7. 没有云账号、云同步、自有云解析，没有不可用功能伪装成主操作。

0.1 是可使用的早期产品，不是“任意视频网站都能下载”的最终版本；支持范围在关于和具体资源详情中说明。

## 9. 后置或不做的事项

后置：完整协议覆盖、直播录制、全套音轨/字幕、内嵌高级播放器、真正无痕隔离、复杂书签目录、任意存储位置、规则体系、大规模自动化平台。
不做：自有云端存储/同步/解析/账号服务、绕过 DRM 或付费/授权控制、虚假的暂停/续传/进度。

历史技术细节保留在 archive/PRODUCT-PLAN-technical-baseline-2026-10-01.md，只作为后续能力实现参考，不再决定当前优先级。
