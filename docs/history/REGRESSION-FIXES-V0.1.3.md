## 修复内容

**嗅探状态缺陷也已落地：** 新导航和 SPA 地址变化会废弃旧扫描 token、释放旧扫描占位。WebView 丢弃旧 evaluateJavascript 回调时，不再永久阻塞扫描；旧回调回来也不能污染新页面或解锁新的扫描。新增两项可控 WebView 回调回归，旧实现两项都失败，修复后两项都通过。完整批次从 223 增至 **225**，没有删除旧用例。

1. **隐私测试的模拟关闭资源**：原 fake `close()` 使用通用 5 秒边界等待；等待到期抛出后，生产包装器按约定释放租约，可能被测试误判成提前释放。改为必须由测试显式释放的 latch；保留“关闭未结束就不能完成静默等待”和“关闭期间拒绝新请求”的安全断言，30 秒整个用例上限和 finally 清理防止真正挂死。这修复了夹具缺陷，不把此前所有失败未经证明地归因于环境。
2. **通知权限前置条件**：普通 UI 下载组合先授予通知权限，避免确认后停在系统弹窗；测试退出恢复原授权。独立通知拒绝专项不改动、不省略。明确选择启用的 HLS 用例，缺 READ/WRITE、通知权限或 Debug 本地请求策略都报失败，不再 silently skip。
3. **Wi-Fi 状态隔离**：直链用例显式设定并断言“不限制 Wi-Fi”，不再盲点切换继承上一个用例的偏好。
4. **产品缺陷：焦点控制器作用域错误**：两个下载确认页及网页/视频改名编辑器在 Dialog 内容外读取 LocalFocusManager/键盘控制器，操作的是背景 Activity 根节点；“完成”后弹窗输入框仍聚焦。把控制器移入 Dialog 内容作用域，并使用强制清焦、显式收键盘；直链/HLS 原用例增加“不再聚焦”断言；编辑弹窗的保存/取消按钮也在 Dialog 作用域读取控制器。
5. **键盘与弹窗状态竞争**：填写文件名后执行现有 Done 动作并断言字段已失去焦点；双格式与综合产品流程通过可见、启用的无障碍 OnClick/OnLongClick 操作执行，普通浏览/直链/HLS 旅程保留触摸输入。快捷站点流程等待实际 IME 关闭、编辑框出现，不依赖固定 600ms 休眠。没有自动重试点击或直接调用产品内部下载绕过 UI。Dialog 与 Activity 是不同窗口，不能用 Activity 的滞后 IME insets 给弹窗增加伪失败门槛。
6. **异步断言条件**：嗅探等待同时覆盖随后要断言的 bad.mp4，避免等前三个候选就抢读第四个；产品操作不依赖 snackbar 在 8 秒内消失。文件改名/忘记/删除、校验哈希、来源恢复的断言全部保留，普通触摸旅程也保留。
7. **失败诊断**：双格式提交失败区分“没有新任务/确认框仍在”与“任务已创建但未校验”；来源恢复失败记录测试页面与选中标签，便于定位，不单报一个等待超时。
8. **可复用验收运行器**：只接受专用 QA AVD，先构建（失败即停止）、计算源码及 APK SHA，设置并恢复权限/屏幕状态，启动和清理本次夹具，现场计算 MP4/WebM SHA，启用所有必要参数，拒绝失败/跳过/少测/崩溃/超时。不会覆盖旧报告，也不会对主模拟器清数据；显式 --reset-lab 仅重置本次可弃用 QA AVD 的 Debug 私有基线，不删除公共文件或正式/原包。

运行方法及边界见 `tools/verification/README.md`；冻结完整范围在 `tools/verification/v013-cohort.json`。
