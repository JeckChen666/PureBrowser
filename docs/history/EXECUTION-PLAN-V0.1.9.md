## 1. 版本定位：保存能力补全 ＋ yt-dlp 规则流水线

> **嗅探与发现已经够厚，本版补"最后一公里"：把目前三类诚实拒绝的下载形态打通（独立音轨 HLS／fMP4 分片／DASH），完成 YouTube 会话路线验证，并把 yt-dlp 提取器语料规模化接入规则生态。**

四条主线：

1. **独立音轨 HLS（TED 型）**：HLS video-variant ＋ audio-rendition 映射进既有 `DualTrackDownloadPlan`（复用双轨传输＋无转码封装机器，是"接线"不是"造轮子"）。解开 TED 及 Apple 风格现代 HLS 一类。
2. **fMP4 分片基础 ＋ DASH 下载**：基于 Media3 `FragmentedMp4Extractor` 做分片轨道组装；先落 DASH（H.264 档）下载，该地基与 AV1 支持共享。
3. **YouTube 会话路线闭环**：v0.1.8 已建 SessionOptIn／WebsiteAccessContext／凭据审计铁轨；T88 已证匿名死路（固定 ≈6.9% 前缀窗口）。**前置：用户在应用内人工登录一次 YouTube** → SESS 电池 → Go 则显式开关整合＋首个 YouTube 双轨成品；No-go 则彻底结案。
4. **yt-dlp 规则转写流水线**：`_VALID_URL` 匹配面机械转写（仅识别，价值有限不入库）＋ 简单提取器（GET API＋JSON 导航类）人工/半自动转写为 v3 fetch 规则；POST/JS 挑战/签名类不可表达（头部站不解锁——预期管理）。首批目标 50–150 条**实站验证**入内置，长尾走导入通道。

成功口径：三率分报、真实新增可用成品结账；新增判据含"独立音轨 HLS 成品"与"DASH 成品"各 ≥1。

## 3. 能力层次与支持合同

- **独立音轨 HLS**：仅限未加密、H.264＋AAC、音视频 rendition 各一（多音轨选默认/首个，多字幕不合并如实提示）；下载中段失败沿用双轨既有清理语义；成品为单 MP4（无转码）。
- **fMP4／DASH**：分片组装走 Media3 extractor；DASH 下载限未加密＋H.264＋AAC（AV1 见 D14）；`m4s` init＋分片顺序与完整性校验；预算并入全局账本；失败不发布半个输出。
- **YouTube 会话**：仅登录态 WebView 会话、显式开关（默认关）、逐跳校验、凭据不落盘；解析仍走匿名 worker，会话只用于媒体传输。
- **yt-dlp 转写纪律**：转写器只产出候选；入内置必须实站成品验证＋夹具；匹配面-only 候选不入库（避免"按钮亮了但必失败"的假覆盖）；审查口径（行为规格转写、无源码文本）随 T94 留痕复核。
- 沿用边界：DRM/付费墙/验证码绕过、远程规则下发、QuickJS（D11 触发未满）不做；FFmpeg 再缓一版（D15）。

## 4. 技术选型

- 零新增依赖（fMP4 用既有 media3-extractor；签名用 JDK 内置 Ed25519）。
- 转写器为 tools/ 下 Python 脚本（离线工具，不进 APK、不受运行时环境约束）。
- 引擎纯度、预算合并账本、加载期校验沿 v0.1.8 §8 全部条款。
