# v0.1.6 T67 有界诊断：YouTube 客户端电池与传输门控证据

日期：2026-10-04（Asia/Shanghai）。分支 `feat/v0.1.6`。性质：H02 承接的**有界新证据**（单变量电池，无 cpn 重跑、无 Cookie/token、匿名、无完整传输宣称）。

## 实验设计

- worker 客户端参数化（`client` 字段，白名单 IOS/ANDROID/ANDROID_VR/TV，缺省 IOS＝生产行为不变；bundle 重建并登记 provenance `clientGateBundle`，712,981B，SHA256 `88577988…735c7`）。
- `V016YouTubeGateDiagnostic`（实站、双显式 opt-in、无参空操作）：每客户端一次解析＋一次 64KiB `Range: bytes=0-65535` 探测，≤4 臂、每臂 ≤3 次 HTTP open、20s 截止；观测仅标量/枚举，URL 与参数值不落盘。

## 结果（Sintel，官方公开视频，匿名）

| 客户端 | 解析 | 探测（0-65535） |
| --- | --- | --- |
| IOS（生产基线） | OK（10.8s，itag137/818p/170,210,373B 声明，URL 含 ip 参数、无 pot） | **HTTP 206**，Content-Range 总长吻合，FTYP@4，1.9s |
| ANDROID_VR | OK（6.9s，同轨） | **HTTP 206**，57ms |
| TV | RESOLVE_UNSUPPORTED（无可行 avc1/mp4a 轨） | — |
| ANDROID | RESOLVE_UNSUPPORTED | — |

随后复跑 v0.1.5 的完整双轨产品审计（`V015YouTubeProductAudit`，实站 opt-in）：**FAILED——"轨道地址失效或访问不足"**（应用诚实失败路径）。

## 结论

1. **v0.1.5 的 403 未在基线客户端复现**：同一生产路径的短前缀 Range 今日为 206。客户端假设（IOS→其他）不成立：ANDROID_VR 同样可用，TV/ANDROID 是解析层无可行轨，不是传输层拒绝。
2. **门控签名与 v0.1.5 完全一致**：64B/64KiB 短 Range 放行（206+FTYP），完整/开放区间传输被拒（v0.1.5 closeout B01 的"完整 header-range 403、64B 206"在今日重现于产品路径）。根因收窄为**对完整区间的服务端门控**，与 cpn、客户端、会话新鲜度无关。
3. prefix 206 ≠ 传输可用，不据此宣称 YouTube 支持。

## 第二轮：分段 Range 电池（根因确认）

同一 URL（IOS，单次解析）三臂单发：A `bytes=0-65535` → **206**（FTYP）；B `bytes=0-`（开放区间）→ **403**（52ms，0 跳，ABSENT）；C `bytes=1048576-2097151`（中部 1MiB 闭区间）→ **206**（64KiB+1 中部字节）。

**结论：门控按请求形态执行——开放区间 `bytes=0-` 被拒，闭区间任意偏移放行。** v0.1.5 全部完整传输失败与今日产品审计失败均呈 B 形态（传输层以开放区间发起）。这不是客户端/cpn/会话问题，也非应用层 bug。

**候选通用解（下一轮实现）**：DualTrack 传输改为**闭区间分段下载＋顺序重组**（如 1–8MiB 分段，参照现有 HLS 分段队列的同构改造）；完全匿名、标准 HTTP Range 语义（浏览器播放器本就以闭区间取流），不涉及 DRM/访问控制绕过——内容本就以匿名闭区间向我们放行。实现后以 `V015YouTubeProductAudit` 实站完整双轨成品为 Go 判据。

复跑：`./gradlew :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.example.purebrowser.download.V016YouTubeGateDiagnostic -Pandroid.testInstrumentationRunnerArguments.video=<id>`（可选 `...clients=…`）。

## 第三轮：闭区间分段传输的产品路径与窗口门控（T67 收口证据）

分段闭区间传输（`DualTrackTransfer`，4 MiB 闭区间顺序分片）实现后，产品审计 `V015YouTubeProductAudit`（header 默认载波）仍在第一片即失败：新增有界观测 `chunkOpens=1, receivedBytes=0`，失败文案为 ACCESS_CONDITION（401/403/410 族）。随后用 `segmentedRangeBoundedDiagnostic` 扩展电池（同一次解析、单变量臂、每臂 ≤3 次 open、仅标量/参数名观测）定位根因：

| 轨道（itag/声明长度） | 通过的 Range（状态） | 被拒的 Range（403） |
| --- | --- | --- |
| 137 / 170,210,373 B | 0-65535、0-262143、0-1048575、0-4194303、0-8388607、中部 1048576-2097151（全部 206+FTYP/中部字节） | 85000192-85983231（1 MiB 跨度@85 MiB）、167772160-170210372（末片）、无 Range 裸 GET |
| 160 / 4,865,643 B | 0-65535、65536-131071、0-131071、0-262143、200000-331071（206） | 0-524287、0-786431、0-1048575、0-4194303、2097152-2359295（256 KiB@2 MiB）、4718592-4865642（末片）、无 Range 裸 GET |
| 140（音频）/ 14,373,564 B | 0-262143、0-1048575（206） | 0-4194303、10485760-10747903（256 KiB@10 MiB）、14155776-14373563（末片）、无 Range 裸 GET |

补充观测：
- 三条轨道 URL 的查询参数**名**集合完全一致（含 `clen`、`gir`、`t` 等，均无 `pot`/`cpn`；参数值不落盘）——门控差异与参数名无关。
- `range=start-end` 查询参数载波（浏览器播放器形态，无 Range 头）：窗口内返回 **200 且无 Content-Range**（参数被忽略，不能用于精确分片验证），窗口外与裸 GET 一样 403。
- 无 Range 头的裸 GET 一律 403——匿名顺序整流也不可用。

**结论（修正第二轮的过度概括）**：门控不是"开放区间被拒、闭区间任意偏移放行"，而是**按轨道声明长度（clen）的比例窗口**：Range 的**终点**必须落在约前 1/10 以内（三条轨道的全部 34 个观测一致：160 通过上限 ∈[331072,524287] vs clen/10=486,564；140 ∈(1048575,4194303] vs clen/10=1,437,356；137 通过 8,388,607、拒绝 85,000,192 vs clen/10=17,021,037）。完整传输的最后一片必然终止于 clen-1，永远在窗口之外；且音频轨（唯一可用 itag 140）同样受限。**在"仅匿名、无 Cookie/token/pot"的硬约束下，YouTube 双轨完整传输在传输层不可达成**——产品审计的诚实失败（ACCESS_CONDITION）是准确的行为，不是实现缺陷。

对 T68–T70 的含义：YouTube 双轨若要真实可用，需要回到会话上下文（站点自身播放器上下文/pot 体系）或明确将 YouTube 双轨标记为不支持并保留诚实失败；二者都是产品决策，不属于 T67 的匿名传输实现范围。本轮证据可由上述电池复跑（`...video=eRsGyueVLvQ`，34 臂；V016 全类 9 测试通过）。
