## 合入结果与 R5 口径

- **入内置 `site-rules.json`：3 条**（`ytdlp-medaltv`、`ytdlp-streamable`、`ytdlp-hitrecord`；id 前缀 `ytdlp-`，文档 version 保持 3，总量 17→20 条）。其余 61 条留候选池（`tools/rules-transcriber/output/`，本地）。
- **抽样成品率：3/3 = 100%（≥60% 达标）**；实测站点 19，其中 SAVE SUCCEEDED 3、发现级 VERIFIED 候选 8、无候选 8。
- **诚实说明**：按“50–150 条”目标衡量本批只入 3 条——根因是 T99 转写的 jsonExtract 指针集取的是上游 JSON 顶层键（启发式），而引擎只对**解析为字符串 URL** 的指针产出候选（数组/对象容器为空产出）。medaltv 是唯一指针直连媒体地址的形态。下一批扩量需要：指针深挖（如 `files.mp4.url`）或数组遍历动作，属 schema 演进，登记为后续任务。
- 8 条 fetch 主机不在 hosts 面内的候选证明现行 D6 白名单与上游“页面域＋独立 API 域”结构冲突，扩量同样需要决策（放宽或双面声明），未在本批内改动。
