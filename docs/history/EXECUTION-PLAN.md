# 当前执行计划：第一轮产品化

日期：2026-10-01（Asia/Shanghai）。
依据：用户已确认 PRODUCT-PLAN.md 中的纯本地、产品化优先方向。
状态：T1–T7 已完成实现与本轮验收。交付和验证证据见 T1-T7-COMPLETION.md。

## 1. 本轮目标

把现有单页面基础程序推进为具有正式首页、多标签、本地书签历史和统一交互的浏览器骨架。
优先呈现实际可操作的产品形态，不增加自有云端能力，不让协议研发阻塞本轮交付。

第一轮交付不是完整 0.1 产品版。下一轮还要完成资源/下载中心及本地视频库的完整产品化，两个阶段一起达到 0.1 标准。

## 2. 本轮范围

### 必须完成

- 统一原生界面的图标、主题、字号、间距与反馈。
- 产品首页：地址/搜索入口、可管理的本地快捷站点、书签/历史入口、最近访问，移除开发说明卡片。
- 多标签：新建、切换、关闭，按标签隔离页面/资源状态，本地恢复标签网址与选中标签。
- 本地书签：添加/取消、列表、搜索、名称/网址编辑、删除。
- 本地历史：记录成功进入的网页、时间列表、搜索、单条删除/清空。
- 地址编辑、键盘、返回、加载/停止、网络错误重试的完整行为。
- 可操作的最小菜单与主题选项；不展示未实现的功能开关。
- 原有资源和下载入口可用，已有直链下载不回归。

### 本轮明确不扩展

HLS/DASH 下载与封装、登录态下载、直播、其他内核、深层 Service Worker/iframe/MSE、复杂播放器、无痕隔离、云端服务、大规模测试平台。
本地视频库、下载分组/文件管理/重试的完整改造属于第二轮；本轮只保持可用入口和统一样式。

## 3. 起始代码约束（以下为实施前状态，本轮已处理）

- BrowserViewModel 起初持有唯一的 BrowserEngine 和 ResourceSniffer；多标签不能继续复用一份全局页面资源状态。
- BrowserEngine 起初 attach/detach 面向单 WebView，detach 会销毁页面；必须区分页面从容器移除与真正释放，避免切换即丢失浏览状态。
- BrowserScreen 起初集中包含首页、工具栏、WebView、资源、下载和确认弹窗；逐步拆分，不能一次改动所有职责却没有清晰边界。
- DownloadRepository 已有任务记录和系统下载服务；不清空现有记录、不迁移为云存储、不为本轮更换下载引擎。
- 资源分类、危险 URL 拒绝、签名参数保留和现有测试继续保留。
- 应用包名和 SDK/Gradle 版本本轮不变，避免无关变动及本地数据归属改变。

## 6. 本轮验收场景

1. 首页输入普通网址或搜索内容，正常进入网页。
2. 打开 A/B/C 三个标签，切换时地址、标题与资源候选对应正确；关闭 B 不影响 A/C。
3. 在 A 发现一个受支持的视频并确认下载，关闭 A 不误取消该下载。
4. 收藏 C、通过历史找回一个页面，修改一个首页快捷站点。
5. 退出并重新打开应用，标签入口、选中标签、书签、历史、快捷站点和主题仍在。
6. 清空历史不删除书签和视频；权限/网络错误不造成崩溃或假成功。
7. 原有签名 MP4 样本仍能经过实际用户操作下载，不能以 UI 重做为由退化现有能力。
