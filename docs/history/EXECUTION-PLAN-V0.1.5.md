## 1. 版本定位：通用能力优先，YouTube 是代表性难点

> **跨站视频发现与保存能力增强版：拓展现有抓取边界，提高多类视频网站上的真实保存成功率；以 YouTube 验证站点适配和双轨能力，而不是把版本做成单站下载器。**

用户补充的优先级已经纳入：**不只是抓取 YouTube，更重要的是面对更多视频网站时提高抓取成功率。** 因此，只有一个 YouTube 专用解析器、其他站点没有进步，不满足本版目标。

主线是 **线索采集 → 媒体识别／关联 → 通用解析 → 必要站点适配 → 统一下载方案 → 受控传输／封装 → 可用成品**。版本成功不是找到更多 URL、识别 blob 或显示更多按钮，而是以前失败的授权样本现在能保存，并且已有成功样本不倒退。

沿用 v0.1.4 的冷灰＋蓝色、顶部地址栏／底部五动作、轻量工具与完整管理页，不做浏览器内核替换、全局 UI 重做或 Logo 替换。用户此前选定 D1 不自动变成本版任务。

### 已确认与待冻结

- **已确认**：跨站抓取成功率提升为首要目标，YouTube 保存纳入 v0.1.5。
- **本计划建议**：优先覆盖无扩展名、动态加载、播放器底层 HTTP(S) 线索、签名／CDN 地址和受限双轨；以固定多站样本验证增益。
- **尚未验证**：各线索的实际可观测范围、JS 运行环境、解析库、格式可用性、包体／内存增量、schema 与最终画质；T51–T54 分别冻结，不提前宣称已支持。
- 默认保留 Apache-2.0 发布策略；规划不是修改项目许可证、登录访问边界或引入云解析的授权。

## 2. 问题基线与失败分类

已发布正式 APK 的官方 Sintel 测试：网页可播放，资源中心 **0 直链／1 blob 页面本地媒体线索**，未创建任务或成品。原始报告在本地 `app/build/reports/youtube/2026-10-03-v014-01/YOUTUBE-DOWNLOAD-TEST.md`，不随源码分发，不将媒体上传 GitHub。

现有实现已有 DOM video/source、WebView GET 观测与资源时间线。请求观测只提交 URL，分类主要依赖扩展名／MIME。无扩展名又缺 MIME 的请求可能被过滤，这是**待验证假设**；不能据单样本断言所有视频网站的根因相同。

按阶段登记失败，而不是统一写“下载失败”：

| 阶段 | 要定位的问题 | 本版改进方向 |
| --- | --- | --- |
| 没发现 | 延迟创建元素、SPA 切片、请求无扩展名、时间线缺信息 | 有界增量观测、多源证据、页面／播放代次绑定 |
| 发现但认错 | 分片／广告当视频、blob 当文件、音轨当有声成品 | 角色分类、作品／播放关联、置信证据，不靠后缀一票决定 |
| 有线索无方案 | 清单、MSE 背后请求、独立音视频、站点专有信息 | 通用 resolver 优先，确需站点知识时才调用 adapter |
| 有方案取不到 | 签名过期、错误 Range、来源限制、格式失配 | 安全有界探测、访问合同、可靠身份、重新解析／明确拒绝 |
| 已取到但不可用 | 单轨、轨道不匹配、封装损坏、文件未发布 | 通用双轨封装、校验、原子发布与真实播放分享 |

Android 官方说明 `shouldInterceptRequest()` 不回调 blob URL；资源时间线也不是无限／无条件完整的网络抓包。具体可观测性、跨源信息限制及需要主动探测的部分必须在测试中披露，不能接管所有请求或复制播放器全部数据来补齐。

## 3. 能力层次与支持合同

### A. 通用发现：不依赖网站名单的主线

- 复用并增强 DOM、请求、资源时间线、播放触发与动态变更线索；必要时在受支持环境评估 fetch／XHR 的最小元数据观测。
- 无扩展名 URL 不再仅因后缀缺失被永久丢弃：进入有界待确认候选，结合可获得的 MIME、响应长度／Range、容器签名及播放关联判断。
- 响应元数据不一定在 WebView 请求回调中可得；先被动采集可用证据，用户主动分析后才允许少量受控探测。不得把每次网页请求变成二次网络下载。
- 区分完整文件、音频轨、视频轨、清单、初始化段、媒体分片、页面本地对象、未知；未知可分析，但不冒充可保存。
- 聚合的是有证据支持的媒体资源／档位，不是同域名所有请求；保留不同作品、广告、签名版本和质量差异。
- DOM／同源 iframe 与跨源／Service Worker／MSE 可观测范围分别报告；不能用注入绕过网页同源或浏览器安全限制。

### B. 通用解析与下载方案：跨站可复用的主线

- 建议建立 `MediaResolver`／`ResolverRegistry` 与版本化 `DownloadPlan`，统一输出单文件、现有受限 HLS、受支持双轨、明确不支持四类结果。
- 先通用 HTTP 媒体／受限 HLS resolver，再按明确站点调用适配器；站点解析结果仍经同一格式、来源、凭据、容器及输出能力检查。
- 无扩展名完整 MP4／WebM、动态发现的受支持 HLS、公开带签名／CDN 地址优先争取新增成品成功，而不只增加线索条数。
- 受支持独立 H.264＋AAC 的完整轨道可通过同一双轨计划无转码封装 MP4；底层传输、封装、恢复和任务 UI 不写成 YouTube 专用。
- 观察到 blob／MSE／MPD 不等于拥有可执行方案。可关联到本版支持的文件／HLS／完整双轨时才允许保存，其余说明能力缺口，不拼接网络片段猜完整电影。

### C. 站点适配：处理通用层不够的地方

- 先提供一个 YouTube 适配器，验证公开匿名单视频、格式选择及独立音视频方案；保持可扩展接口，而不是为每个站点复制下载器。
- YouTube watch／移动 watch／youtu.be 严格校验真实 host、URL 结构与 videoId，不展开播放列表，不导入登录凭据。
- 其他站点先依靠通用层获得增益；T51 样本若证明确需适配器，依据失败模式及许可评估最多追加一个有明确范围的适配，不临时堆站点名单凑数量。
- 适配只解决信息／方案获取；队列、网络安全、持久化、封装及发布属于公共核心。

### 支持与排除

| 场景 | 定位 | 限制 |
| --- | --- | --- |
| 原有公开直链／限定 HLS 点播 | 必须保持 | 旧成品、任务、恢复及浏览链路不回归 |
| 无扩展名、动态媒体、公开签名／CDN、可关联 blob 底层线索 | 通用核心 | 必须以非 YouTube 真实新增成功验证；发现线索不等于可保存 |
| H.264 视频＋AAC 音频完整轨道 → MP4 | 公共新能力 | 无转码、有界封装；首版上限建议 1080p，实际格式 T54 冻结；不是通用 DASH 宣称 |
| 公开匿名且获授权的 YouTube 点播 | 代表性核心难点 | 至少一个实际双轨成品；只展示实际返回的受支持档位，不硬编码 itag |
| 现有合法限定网站会话能力 | 保持原合同 | 不因新通用／站点解析扩大 Cookie 跨源转发；匿名样本作为新链路基线 |
| 过期、需访问授权、无支持格式、适配失效 | 必须说明 | 有界重解析／明确拒绝，不假成功、不无限重试 |
| DRM、付费／地区／年龄限制绕过、验证码／额外验证绕过 | 不做 | 可播放／可访问不等于有权保存；不提供规避访问控制路线 |
| 直播、批量、频道／播放列表、Shorts 专项、音频／字幕单独导出 | 不纳入 | 不展示假操作；普通单视频与特殊页面分别验收 |
| 通用动态 DASH／MPD 分片全覆盖、MSE buffer 导出、AV1／VP9＋Opus 双轨、4K／转码 | 不承诺 | 记录协议缺口，后续根据失败数据独立规划；保留旧受支持 WebM 直链 |
| 云解析／云 token 服务、远程解析插件热更新 | 不做 | 纯本地处理，固定依赖和正常应用更新 |

## 4. YouTube 技术关口：不能取代跨站目标

| 候选 | 已知来源／许可 | 决策规则 |
| --- | --- | --- |
| YouTube.js | MIT；JS 环境／网络能力及部分流地址处理的解释器有要求 | 默认许可路线下优先 Android 小型验证，尚未选定运行时／依赖 |
| NewPipeExtractor | Java 提取库；GPL v3-or-later | 原生备选；无明确用户许可决策及分发审查，不接入发布构建，不照搬 GPL 实现 |
| yt-dlp ＋ youtubedl-android | 核心与打包许可不同；Android 封装 GPL-3.0，涉及 Python／原生组件；YouTube 支持涉及 EJS／JS runtime | 行为对照候选，不默认引入 Python／FFmpeg，不绕过应用队列 |

T54 必须形成固定版本／提交、传递依赖／归属、包体／内存／耗时与安全运行条件的决策记录。Android 上匿名授权样本须产生可验证格式，并可由公共传输层读取真实轨道字节；桌面 CLI 返回 URL 不算。

Go 要求：受控网络、有限重试、可取消／超时、运行环境无任意文件／Java 桥／命令权限；不用账号 Cookie、云服务、TLS 放宽或访问控制绕过补救。实际支持的格式与预算在此冻结。

若 YouTube 路线 No-go，通用能力工作可以继续，但本版不能宣称已支持 YouTube；必须报告所需许可／运行时决策或提议调整范围。反过来，只有 YouTube 成功、非 YouTube 无增益，也不能满足跨站增强版的放行目标。

## 5. 公共核心合同

### 5.1 有界观测、关联与回退

- 所有线索／异步探测带 tab／页面代次／播放身份／操作 ID；SPA 换视频、自动连播、导航及关闭后丢弃旧回调。
- fetch／XHR 元数据观测若采用，必须保持网页调用语义，不读取／外传请求正文、凭据或播放器全部响应；只在受控来源和生命周期工作。平台不支持时回退现有观测，不破坏网页。
- 解析／探测按用户动作触发，时间、次数、响应大小、候选数、重定向、并发及缓存预算在 T51／T52 固定；响应不支持 HEAD 或 Range 时不无限拉流。
- 被动线索不自动成为高置信文件；主动探测也不能只因 Content-Type 是 video 就判定完整。字段互相矛盾、只有部分轨道或校验不足则维持待确认／不支持。
- 不删除 query 做通用去重，不把同域名、同标题、相近时间当同一作品的充分证据。站点格式身份与请求身份分开。

### 5.2 统一方案与安全访问

- 拟新增版本化 `DownloadPlan`／resolver 接口；`MediaCandidate` 继续是线索，不塞入站点专用执行逻辑。旧单文件／HLS 计划通过明确兼容层保留。
- 稳定身份包含资源／作品、所选格式／轨道、输出能力、校验信息及 resolver 版本；运行期签名 URL／会话材料与稳定身份分离。单次解析结果有时效。
- resolver 输出不自动可信，逐跳经过 `RequestPolicy` 的 HTTPS、host／来源、凭据、重定向及降级检查；不为“更多网站”扩大全局 Cookie 资格或关闭 TLS。
- 匿名站点与 CDN 不跨源带入浏览器 Cookie／Authorization；已有合法会话流程遵守原合同。探测、重新解析与实际下载使用一致的访问边界。
- 隔离解析执行与业务文件／网页 WebView；不向任意网页开放特权桥，不执行用户任意命令或任意 URL 返回的代码。必要播放器处理限定来源及执行权限并接受安全审查。
- 查询参数／token／Cookie 不进诊断、公开夹具／普通 UI；新的临时解析结果不作为长期恢复凭据。适配依赖固定，更新通过正常应用发布。

### 5.3 公共传输、双轨、封装与恢复

- 复用 TaskId、2 任务队列、FGS、公共目录发布／文件归属；所有新探测／轨道请求纳入全局预算，不因两轨复制并发额度。
- 一部资源一个任务；每轨下载与校验是内部阶段。单轨失败不发布另一轨为完整电影，未知总量不造百分比。
- 优先验证现有 Media3 extractor／muxer 用于通用 H.264/AAC 双轨，不能把 TS→MP4 旧流程直接套用；不默认引入 FFmpeg、不转码。
- 校验轨道身份、codec、时戳／时基、起始偏移、时长及样本可读性；两轨下载后封装／校验／事务式发布，最后才显示已完成。
- 磁盘／内存有界，容量预估覆盖双输入＋输出＋余量。取消／进程死亡／发布失败按归属清理，不删其他任务或已有成品；半个输出不能直接续写冒充恢复。
- 暂停／取消／继续／重新下载按真实阶段能力展示；冷启动对账、用户主动恢复，不承诺强停后继续运行。
- 过期／403 只允许有界重新解析；作品／格式／轨道／强校验信息不同不能拼接旧字节，无法可靠续传时解释需要重新下载并让用户确认。
- 老 v5 任务保留旧引擎路径；若需新 schema，T55 冻结迁移、原始备份及异常恢复，不能把共享引擎变化说成纯 UI 免回归。

### 5.4 UI：展示真实能力，不展示站点特例堆积

复用资源面板／完整资源页，区分网络、元素、探测和站点解析证据。入口可为“分析当前视频”，有取消、未发现／需要授权／协议或格式不支持／过期／适配失效等状态。

格式确认显示实际画质、容器、已含音视频或需要合并、已知／未知大小及保存权利提示；用户确认才创建任务，连点／取消／切页不重复入队。下载阶段、合并、校验、发布分开，打开／分享／移除记录／物理删除沿用旧合同。

浅深色、大字体、窄屏、系统返回、焦点／TalkBack 不回归；不重新设计整体 UI，不把解析失败统一包装成网络错误。

| T59 | 固定跨站 A/B、真实成品与安全／升级／旧链路回归 | T52–T58 | 非 YouTube 新增成功且旧成功保留、YouTube 实际双轨成品；M1–M9 有证据，公开失败／分母，不挑成功样本 |
| T60 | 正式签名冻结、精确最终包烟测与发行材料 | T59 | M10 通过，源码／版本／APK／证书／hash 一致后才 tag／Pre-release，不把计划写成完成 |

代码落点相对 `app/src/main/java/com/example/purebrowser/`，是建议职责，不是已存在接口或一次性重写要求。

### 实施顺序与可并行点

1. 主执行者先处理关键路径 **T51→T52**：冻结测量与公共接口，再做通用层改进。
2. T54 YouTube 可行性可与 T52 通用观测并行；不能把 T54 成功当通用增益。
3. 合同冻结后，T53 resolver、T55 持久化基础、T57 自制夹具／封装、T58 fake UI 可以不重叠分工；整合依赖仍如表。
4. T56／T57／T58 整合后 T59，再 T60。共享 schema／状态机／网络安全核心先统一，不允许多人各自改同一核心文件。

## 7. 成功率与样本门槛

具体口径见 [跨站样本与对比合同](COMPATIBILITY-CORPUS-V0.1.5.md)，建议在 T51 冻结：

- 至少 **8 个不同授权真实作品、4 个独立视频网站／服务**；其中 YouTube 2 个（含 Sintel）、非 YouTube 至少 6 个、覆盖至少 3 个独立服务。自建测试服务器、同服务子域／CDN、同作品多画质不凑数量。
- 三个指标分别报告：**线索发现率、可执行方案率、可用成品率**。核心是成品率；候选条数和解析成功率不能替代它。
- 使用已发布 v0.1.4 与候选、相同设备／WebView／网络／匿名状态／步骤，对同一冻结样本逐项配对。保留未知、站点变化、未测和失败，不从结果中反选分母。
- 至少 **2 个旧版失败、候选成功的非 YouTube 样本，分属 2 个独立服务**；至少一个新增成功来自通用层，不只靠站点专用 adapter。记录具体是哪层改进。
- 旧版已成功的受支持样本不得倒退；若环境变化，明确不可比并补足有效配对，不能强算新旧差异。
- YouTube 至少一个实际双轨成品仍是必要项；只获得跨站线索但不能保存，或只有 YouTube 成功，都不放行。
- 新样本成功须校验文件／轨道／时长、首中尾实际声画、播放与跨 UID 分享；没有声音验证就不能声称有声成品。
- 自制夹具补动态、同源 iframe、无扩展名／错误 MIME、Range／过期、分片／广告、两轨 mismatch、生命周期故障；不代替真实网站增益。

不预先承诺“全网成功率 95%”或“支持所有 blob”。小样本只证明所测版本与条件，未知边界公开保留。

## 8. 安全、性能、恢复与放行

详见 [M1–M10](RELEASE-ACCEPTANCE-V0.1.5.md)。沿用 JUnit／coroutines-test、Android instrumented／Compose／Espresso 与主机工具，以可注入 resolver／clock／network 和合法媒体夹具验证，不为本版引入整套新测试平台。

API28／36／37 分层覆盖存储、分享、后台／系统限制及新链路；公共引擎变化须重跑受影响直链／HLS、15 分钟后台及大／长任务，不能继承 UI 版的免测理由。code13→候选同包同证书升级，旧任务／成品／书签等不丢失。诊断脱敏、JS 权限隔离、凭据／重定向保护、输出真实与精确签名 APK 是硬门槛。

风险按失败层处置：观测不全则如实回退；协议不支持则说明；适配失效则有界重试；许可路线不可用则决策 No-go；持续内存失控、ANR、旧成功倒退、成品损坏／假完成、凭据泄漏或访问绕过阻挡发行。不能因为跨站目标扩大而放松安全。
