# v0.1.8 AV1/fMP4 边界评估（仅评估，不实现）

日期：2026-10-04。分支 `feat/v0.1.8`。任务来源：v0.1.7 验证证据 S-D/S-F（AV1/fMP4 清单被解析器白名单诚实拒绝）、执行计划 T91 第三项、发行验收 R7 第三项。本文只做工程评估，不含任何实现；结论供另版立项决策。

## 结论（先行）

**建议本版维持现状**：`HlsPlaylistParser` 对 `#EXT-X-MAP` 等 fMP4 形态继续诚实拒绝（UNSUPPORTED「清单包含本版不支持的媒体特性」），不实现 AV1 支持。理由：当前登记在册的 AV1-only 阻断站点仅 2 个（S-D、S-F，同属 xplayer 形态家族），而完整支持预估 ~800–1200 行代码与一轮 API28/36/37 矩阵复验，且 minSdk26–28 存量设备无平台 AV1 解码，成品「本机可打开」口径会被迫按 SDK 门控。**触发再评估的条件**：登记的 AV1-only 阻断规则站点超过 3 个，或出现产品级高优站点仅提供 AV1 档。立项前先完成一项前置诊断（见文末）。

## 输入证据（v0.1.7 实测，出处 V0.1.7-VALIDATION-EVIDENCE.md）

- S-D/S-F：站点 2026-10 起仅引用 AV1 清单族（`_TPL_.av1.mp4.m3u8`，全部变体 fMP4＋`#EXT-X-MAP`）；同路径存在 `.h264.` 后缀的 H.264 回退主清单（curl 可取、TS 分片），但页面对具备 AV1 解码的设备从不引用；S-F 以 `forcedUserAgent` 双 UA 实测均仅获 AV1 引用。
- 拒绝点链：`HlsPlaylistParser.excludedTags`（`#EXT-X-MAP`/`#EXT-X-BYTERANGE`）→ `checkSegmentUrl`（m4s/mp4 分片扩展名）→ `TsToMp4Remuxer`（仅 MPEG-TS＋H.264＋AAC）。档位层 CODECS 非 `avc1/avc3/mp4a` 已是「可选但告诫」警告，UX 诚实。

依赖现状：`androidx.media3:media3-extractor/muxer 1.11.1`（无 exoplayer/decoder）。Media3 的 FragmentedMp4Extractor 与 Mp4Muxer 为纯 Java 实现，av1C 解析与 av01 sample entry 写出在库内完成，不依赖平台解析器，API26+ 行为一致（假设 A3）。

## 设备解码可用性（公开资料，均标记为假设，未经本仓库实测）

- 软解：Android 10（API29）起平台自带 AV1 软件解码器 `c2.android.av1.decoder`（libgav1）［假设 A1］；Android 9 及以下无平台软解。
- 硬解：2020 年起旗舰 SoC 逐步配备（Dimensity 1000 系列、Tensor、Exynos 2200、骁龙 8 Gen 1 及之后）［假设 A2］；本应用 minSdk26–28 对应的存量设备基本无 AV1 解码能力。
- 关键澄清：保存/封装路径不解码（remux 仅搬运压缩采样），解码能力真正影响两点——(a) 站端能力协商：设备支持 AV1 时站点只发 AV1 档（S-D/S-F 实测行为）；(b) 成品在本机「可打开」验收：API28 设备上保存出的 AV1 MP4 本机无法播放，只能转存后在他机播放，与现有「可打开成品」验收口径冲突，需按 SDK 门控（仅 API29+ 提供 AV1 保存）或放宽验收定义。

## 规模与风险估算

- 代码 ~800–1200 行（含 JVM/设备测试），量级相当于 v0.1.2–v0.1.5 TS 封装链路的重做；验收需重跑 API28/36/37 分层矩阵与 HLS 全套冻结场景。
- 最大技术风险：平台 MediaExtractor 对 av01 的解析差异（A4，决定 SDK 门控设计）；`EXT-X-BYTERANGE` 形态的站点差异（每段非整文件时需 range 请求拼装）。

## 替代方案评估

- **转码 AV1→H.264**：需 MediaCodec 解码＋编码管线，功耗/耗时/质量损失，且违反本产品既有红线（`TsToMp4Remuxer` 头注声明 no transcoding）。否决。
- **能力伪装诱导 H.264 档**（UA/解码能力声明）：S-F 双 UA 实测无效；即便个别站点有效也属脆弱的发现层伪装，不作能力承诺。否决（`forcedUserAgent` 保留为站点级诊断钩子）。
- **仅支持 fMP4/H.264（不含 AV1）**：工作量约完整方案一半，覆盖 fMP4＋H.264 站点，但 S-D/S-F 均 AV1-only，不解当前阻断站点；可作完整方案的第一个里程碑。

## 建议与触发条件

1. 本版维持诚实 UNSUPPORTED，消息文案不变。
2. 立项前置诊断（约半天）：API28 与 API37 各一台真机/模拟器，探测平台 MediaExtractor 对 av01 MP4 的 track/duration/采样可读性，结论写入本文档附录，决定 SDK 门控设计。
3. 触发条件：登记的 AV1-only 阻断规则站点 >3 个（现 2 个），或产品级高优站点 AV1-only；届时按「清单层放行 → fMP4/H.264 → AV1」两里程碑立项。
