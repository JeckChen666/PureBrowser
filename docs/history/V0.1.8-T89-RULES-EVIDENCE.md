## 新增 v3 规则（6 条）

1. `archive-org-embed`：hosts `(^|\.)archive\.org$`＋path `/details/<id>` 捕获组；fetch `https://archive.org/embed/{{m1}}`（131072 B 上限）；regexExtract `(https://archive.org/download/[^"\s]+\.mp4)`。
2. `ted-talks-inline`：hosts `(^|\.)ted\.com$`＋path `/talks/<slug>`；无 fetch；regexExtract 于内联 JSON 收割 `"hlsUrl":"(https://…m3u8…)"`。
3. `commons-file-videoinfo`：hosts `(^|\.)wikimedia\.org$`＋path `/wiki/(File:<title>)`；fetch `…/w/api.php?…formatversion=2&prop=videoinfo&viprop=url%7Cderivatives&titles={{m1}}`（65536 B）；jsonExtract `query.pages[0].videoinfo[0].url`＋`derivatives[0].src`。
4. `dailymotion-metadata`：hosts `(^|\.)dailymotion\.com$`＋path `/video/<id>`；fetch `https://www.dailymotion.com/player/metadata/video/{{m1}}`（65536 B）；jsonExtract `qualities.auto[0].url`。
5. `peertube-blender-files` / `peertube-framatube-files`（两条，同一形状不同实例）：hosts 各自实例域＋path `/w/<shortUUID>`；fetch `…/api/v1/videos/{{m1}}`（65536 B）；jsonExtract `files[0..5].fileDownloadUrl`。

装载期校验全部通过（session 缺省、fetch https、maxBytes 有界、占位符被 path 捕获组绑定）；JVM 侧 `SiteRulesAssetTest`（白名单扩展＋5+1 目标在位断言）与新增 `SiteRulesV3TargetsTest`（7 用例，.example 通用域夹具：四形状端到端提取、数字键指针拒绝、未绑定占位符拒绝、主文档独占绑定）。

## 配套修复（本轮发现并落地，均有 JVM 覆盖）

- **RuleEngine 主文档补位**：WebView 主文档拦截与页面纪元翻转存在竞态（主文档请求带着旧纪元被丢弃），页面 URL 从未进入 path face 输入。引擎现按契约把 pageUrl 追加进匹配输入（纯引擎改动，`SiteRulesV3TargetsTest.mainDocumentAloneBindsThePathFaceEvenWithNoObservedRequests`）。
- **AutoProbeQueue 跨源跳转剥离 Cookie**：同源页面会话 Cookie 在跨源跳转上不再整场失败，而是剥除后匿名续链（Cookie 永不出同源边界；https 降级仍拒绝）。解锁 archive.org 下载节点 302。`AutoProbeQueueTest` 新增 2 用例（剥离重试、降级仍拒）。
- **HlsPlaylistParser 片段丢弃**：变体行携带的 `#cell=` 类片段是客户端提示、HTTP 永不传输，现解析前剥除而非整单拒绝（scheme/host 等校验照旧）。解锁 Dailymotion 主清单。`HlsPlaylistParserTest` 断言更新＋新用例。
- **SaveSmoke 选择器**（仅测试装配）：当生产 HlsResolver 拒绝某 HLS 主清单（如 fMP4 独立音轨）时回退最佳 FILE 档，忠实反映"用户改选可下载档位"。

## 诚实记录与遗留

- TED/Wikimedia 的 SAVE 缺口均为**产品级**（独立音轨支持、上传集群限流下的重试/退避），非规则层问题；两站发现与验证链路已全绿，登记为后续候选。
- 规则产物中 jsonExtract 档位高度多为空（指针文法不携带数值），档位高度来自探测变体（HLS）或 URL 后缀（PeerTube 文件名内嵌 1080/480）；R5 的"选定清晰度"在直链站以档位行选择呈现。
