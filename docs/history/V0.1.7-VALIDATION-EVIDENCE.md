## R3 规则层真实站点端到端（≥2 站真实成品）

候选路线说明（如实登记）：reddit（reddit-post 规则）与 VK（vk-video-api 规则）为本轮首选，但当前执行环境两条路线均被登录墙拦截（old.reddit.com/.json 302 至登录页、www 403，自定义 UA 亦然；VK /video 302 至登录页）；anyporn（tube-kvs-alt-watch 规则）列表页与 KVS 异步块接口均要求登录（异步块返回空壳）；Dailymotion（无专属规则的备选）页面可开但播放器在跨源 iframe 内且无手势不拉清单（0 候选）；Vimeo（vimeo-player-config 规则）页面可开但播放器配置请求发生在跨源 iframe 内，v0.1.7 响应截获层只挂主帧 fetch/XHR（浏览器同源安全边界，设计使然），发现冒烟 0 候选。按"顶文档播放器"约束改用 v0.1.7 规则批次覆盖的站点（脱敏代号 S-C/S-D/S-E）。

R3 结论：**部分达成（规则层 1/2 站成品）**。S-C 为规则层完整成品；S-D 规则命中与档位提取全部生效（master＋5 档 VERIFIED），但该站 2026-10 起页面仅引用 AV1 清单族（全部变体为 fMP4＋`#EXT-X-MAP`，本版解析器按白名单拒绝），页面对 H.264 回退主清单（同路径 `.h264.` 后缀，curl 可取且为 TS 分片）从不发引用——仅当设备解码不支持 AV1 时播放器才会请求，属解析器能力边界而非发现/规则层倒退；S-E 证明该站通用层可端到端保存真实 MP4，但其完整正片主清单（3 变体 VERIFIED）因 URL 以 `.mp4` 结尾被沿用 v0.1.6 的 URL 分类判为 `kind=FILE`（首次观测时 MIME 未知、探测确认 mpegurl 后 kind 不回填），生产 UI 按 kind 路由无法对其走 HLS 下载——登记为 v0.1.8 增强级跟进（主清单 kind 回填/MIME 重判），不属 v0.1.7 回归。
